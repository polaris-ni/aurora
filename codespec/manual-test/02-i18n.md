## 1 适用范围与约定

### 1.1 被测模块

`include/aurora/i18n/` —— Aurora 的**国际化运行时**（8 个公共头：`format.h`、`locale.h`、`localized_string.h`、`message_catalog.h`、`message_id.h`、`plural.h`、`builtin_messages.h` 与其生成件 `builtin_messages.gen.h`），在实测依赖分层中位于 L0：其公共头**不依赖任何其他 aurora 模块**，只依赖自身与标准库（规格落点见 `codespec/specification/07-environment-modifier.md` §6）。构建期半边（`tools/gen/gen_i18n.cpp` 生成的强类型词条头与 `AUM1` 二进制词表）经本载体的真实消费路径一并覆盖。

`i18n/` 的可观测行为分两类：

| 载体 | 内容 |
|:---|:---|
| 经文本控件渲染的最终文案 | `LocalizedString` 字面量呈现、`tr(MessageId)` 查表解析、**缺译回退**、复数 / 序数 / 选择分支与数字 / 货币 / 日期格式化结果、`Locale` 经 `LocaleProvider` 的注入与**运行期换档重解析**语义（解析发生在 `include/aurora/widget/text.h` 的渲染路径：`resolve(&default_catalog(), loc)`） |
| 纯函数格式化 | `format_number` / `format_currency` / `format_date` 与 `plural_category` 的类别映射——输入输出有唯一解，人工判定无增益，全部归单元测试（见 §1.8） |

### 1.2 执行载体

本模块复用既有窗口载体 `examples/demos/demo_i18n.cpp`（构建目标 `demo_i18n`）。它是**窗口程序**：经 `examples/demos/demo_common.h` 的 `run_demo` 创建标题为 `i18n · Aurora Demo`、逻辑尺寸 560×420 的普通窗口，人工判定发生在**窗口画面**上；控制台只承载诊断日志（stderr），功能输出（stdout）恒为空。

载体的能力边界（决定 §1.8 的覆盖取舍）：

- **词条全部来自外部词表**：`examples/demos/i18n/messages_en.json`（基准档 `en`）与 `messages_zh-Hans-CN.json`，由 `aurora_i18n_generate` 在构建期产出 `messages_en.hpp`（强类型 Id 常量与具名形参构造函数 `demo_i18n::msg::demo::*`）与 `messages_en.bin`（`AUM1` 词表，全语言合一）。载体源码不含任何译文字面量。
- **运行期可换档**：`LocaleProvider` 注入 `State<Locale>`，初始 `Locale{en}`；窗口内一枚 `Switch locale (en / zh-Hans-CN)` 按钮翻转该状态，五条文案随 locale 即时重解析。
- **词表载入有回退**：读不到二进制词表时打一条 `ERR` 日志并继续运行（文案落回 `LocalizedString::text`，本载体该字段为空 → 空文本），不崩溃。

| 约束 | 落地方式 |
|:---|:---|
| 不新增公共 API | 只调用既有 `include/aurora/i18n/` 公共头与 `demo_common.h` 本地控件 |
| 载体形态 | 窗口程序：人工在窗口上观察文案呈现；关闭窗口即退出 |
| 判定可复现 | 窗口文案由编译期词表 + 编译期入参决定，无随机数与真实时钟；日志的时间戳/线程 id/行号为唯一可变部分 |
| 与单元测试不重叠 | 载体**只演示、不断言**，不输出 PASS/FAIL；缺译回退与换档刷新等契约由人工对照窗口判定 |

**取证通道**：本机为交互桌面会话时可直接看窗口；若窗口被遮挡或不便操作，可用 `AURORA_INSPECTOR_PORT=<port>` 启动载体后以 `build/aurora_e2e_client.exe --port <port> snapshot fb -o <png>` 取窗口帧缓冲出图、以 `tap <path>` 触发按钮（`Inspector::simulate_click`，直投控件点击回调）。两条通道判读的是同一份画面，结论等价。

### 1.4 用例编号规则

格式 `TC-<模块段>-<三位序号>`，自 001 起连续编号。
模块段为**模块目录名的大写形式**（`core` → `CORE`、`i18n` → `I18N`；取 `include/aurora/` 下的模块目录名，本目录文件名前缀 `NN-` 是文档序号、不计入模块段，如 `01-core.md` → `CORE`），**不得自创缩写**——目录名含数字时数字原样保留，故正则为 `^TC-[A-Z0-9]+-\d{3}$`。
本模块目录名 `i18n`，即 `TC-I18N-001` 起。序号在本模块内唯一且**不复用**；用例被删除后其编号作废，新用例取下一个可用序号。
用例在文档中**按编号升序声明**——该顺序即默认执行顺序，也是依赖列表排序的依据（见 §1.5）。

### 1.5 用例字段清单与格式规范

每条用例由**六个固定字段**组成，排布于同一张 Markdown 表格内。**字段顺序固定、字段名一字不差、每字段独占一行、单元格内不换行**（需要多条内容时用 `<br>` 分隔）：

| 序号 | 字段 | 格式 | 正则约束 | 说明 |
|:--:|:---|:---|:---|:---|
| 1 | 用例编号 | 单行 | `^TC-[A-Z0-9]+-\d{3}$` | 模块内唯一且不复用 |
| 2 | 测试目的 | 单行 | 自由文本 | 一句话，指向**单一**验证目标 |
| 3 | 前置条件 | 单行 | 自由文本 | 只描述**环境状态**；「必须先执行某用例」属依赖用例字段，不在此重复 |
| 4 | 依赖用例 | 单行 | `^无$` 或 `^TC-[A-Z0-9]+-\d{3}(, TC-[A-Z0-9]+-\d{3})*$` | 见下方规范 |
| 5 | 操作步骤 | 条目列表 | 每条目以 `^\d+\. ` 开头，条目间以 `<br>` 分隔 | 自 1 起连续编号 |
| 6 | 预期结果 | 条目列表 | 同操作步骤；编号是步骤号的**子集** | 见 §1.6 |

**依赖用例字段规范（四条硬性要求）：**

1. 无依赖时**必须**写 `无`，不得留空、不得写 `-`、`N/A`、`none` 等变体。
2. 有依赖时写**用例编号全称**（含模块段），不写省略形式；跨模块依赖同样写全称。
3. 多项依赖以**半角逗号加一个空格**（`, `）分隔；逗号前后不得出现空格以外的字符。
4. 多项依赖的**排列顺序即依赖先后**——先决者在前。因用例按编号升序声明，等价于按被依赖用例的**编号升序**排列。

**模块级约定**：本模块载体的构建步骤统一置于 `TC-I18N-001` 的步骤 1；其余用例不在步骤中重复构建，而是通过依赖用例字段间接依赖其产出的已构建载体。

**为什么必须统一格式**：本文件由 `tools/check/check_manual_test_format.py` 解析守护（CTest 用例 `check_manual_test_format`，校验字段名与顺序、取值域、依赖拓扑、步骤-预期同号映射与执行记录表格式）。上述约定使每个字段可用**单条正则**校验，无需自然语言推断。

### 1.6 操作步骤与预期结果编号规则

**预期结果与操作步骤同号一一对应**：`预期结果 N` 即「步骤 N 的对应结果」。

1. 预期结果的序号**等于**其对应步骤的序号，两者严格相等——不得因省略而重排、压缩或重新连续编号。
2. 纯执行步骤**不产生预期结果**，其序号在预期结果列表中直接跳过。
3. 故预期结果的序号**不要求连续**，条数也无需等于步骤数。
4. 步骤列表中，纯执行步骤在文本末尾标注「（纯执行，无预期结果）」，供与预期结果列表逐号对照。

示例：某用例有步骤 1、2、3、4，其中步骤 3 为纯执行步骤，则该用例的预期结果共 3 条，编号为 1、2、4。

**该规则解决的问题**：执行者按步骤顺序推进时，编号本身即是映射关系，无需自行推断「这条预期结果对应哪一步」；执行记录可借步骤号精确落到失败点。

### 1.7 判定与记录

| 结果 | 含义 |
|:---|:---|
| PASS | 全部非空预期结果均满足 |
| FAIL | 任一非空预期结果不满足；须在记录表登记该预期结果对应的**步骤号**、实际现象与缺陷编号 |
| BLOCKED | 前置条件无法满足（如载体构建失败），未开始执行 |
| SKIP | 主动判定不适用于本环境（如无窗口会话时的窗口类用例） |

输出中含**时间戳、线程 id、文件行号**的字段属可变部分，判定时只核对格式与是否出现，不比对具体值。

**执行记录表格式**（列顺序固定）：

| 列 | 格式 | 允许值 / 正则 |
|:---|:---|:---|
| 用例编号 | 单行 | 与 §2 用例编号一致 |
| 执行日期 | 单行 | `^\d{4}-\d{2}-\d{2}$` |
| 执行人 | 单行 | 自由文本 |
| 结果 | 单行 | `PASS` / `FAIL` / `BLOCKED` / `SKIP` |
| 失败步骤号 | 单行 | 留空（未失败或未执行），或 `^\d+(, \d+)*$`（多个以半角逗号加一个空格分隔） |
| 实际现象 | 单行 | 自由文本 |
| 缺陷编号 | 单行 | 留空或缺陷单号 |
| 备注 | 单行 | 自由文本 |

未执行的取值一律**留空单元格**，不写 `-`、`TBD`、`N/A` 等占位符。

### 1.8 覆盖取舍

本模块按「人工判定是否优于程序判定」取舍，并受载体能力约束（`demo_i18n` 具备多语言词表与区域切换交互）。

**纳入人工测试的子域**（人工能判得比程序准，且现有载体可观测）：

| 子域 | 人工判定优于程序判定的原因 |
|:---|:---|
| 缺译回退的用户可见后果 | 「回退为空文本、不显示词条名/占位符、不报错不崩溃」最终落在用户看到的画面上；程序只能断言返回值为空串，无法判断画面是否可接受 |
| 文案呈现质量与格式化语感 | 逐字一致性、字形质量、有无乱码与缺字形方框，以及复数 / 序数 / 日期 / 货币读起来是否自然，属视觉与语感判断 |
| 运行期换档的刷新完整性 | 「点一下按钮整屏文案一起换、且换回来画面复原」是跨帧的缓存失效不变量，程序断言只能覆盖单点，人眼一次看全 |
| Locale 注入语义 | 「显式注入而非取自进程环境」需人为改变环境变量后对比画面，属环境核对 |
| 非 ASCII 字符的编码链路 | U+00B7 经「窗口标题（ACP 转换）」与「控制台日志（UTF-8）」两条链路，人眼判定是否丢字最直接 |
| 无窗口降级出图 | 「降级而非静默失败」是控制流不变量：需确认进程确实产出 PNG 并退出，而非仅返回了对象 |

**不纳入人工测试的头与子域及其理由**：

| 头 / 子域 | 理由 | 已有覆盖 |
|:---|:---|:---|
| `locale.h` | 纯值类型，`tag` 拼接有唯一解，人工执行无增益 | `tests/unit/utest_locale.cpp`（6 用例） |
| `message_id.h` | 纯值类型与哨兵常量，比较语义有唯一解 | `tests/unit/utest_message_catalog.cpp`（Id 与哨兵段） |
| `plural.h` | 纯函数，CLDR 类别映射有唯一解；载体只演示单一样例 | `tests/unit/utest_plural.cpp` + `tests/unit/plural_rules_samples.gen.inc`（CLDR 48 全表 3512 条样例穷举） |
| `format.h` | 纯函数，数字/货币/日期输出有唯一解，人工抄录反增误差 | `tests/unit/utest_format.cpp`（4 用例） |
| `message_catalog.h` 的查表、回退链与 `AUM1` 载入校验 | `add`/`resolve`/`load_binary`/`missing_translations` 的精确结果与结构化错误码程序判定更准 | `tests/unit/utest_message_catalog.cpp`（18 用例）、`tests/integration/itest_i18n_pipeline.cpp`（7 用例）+ CTest 门禁 `check_i18n_gen_golden`（七条腿） |
| `builtin_messages.h` 的内置词条 Id ↔ 规范名契约 | 是编译期常量表，字面量钉死即可 | `tests/unit/utest_message_catalog.cpp` 与 `tests/unit/utest_command_palette.cpp` / `utest_reorderable_list.cpp` 各自以英文字面量比对 |
| RTL 表现 | 载体无 RTL 语言档，**无观测路径**；如需覆盖应先扩展载体词表（属新增代码，须另行按 clang-format / clang-tidy / 构建三步门禁立项），本文档不留占位用例 | `utest_format` / `utest_message_catalog` 对方向无关的格式化与查表结果已穷举 |

### 2.2 Locale 注入与环境无关性

### 2.3 缺译回退与文案呈现

#### TC-I18N-003 缺译回退为空文本且不报错

| 项目 | 内容 |

| 用例编号 | TC-I18N-003 |

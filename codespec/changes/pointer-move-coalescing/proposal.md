## 动机

指针移动是交互态下频率最高的事件：操作系统按输入设备采样率投递，常达每秒数百次，而渲染只有每帧一次。当前每个移动事件都完整执行一次根节点 `hit_test_chain`（自顶向下遍历候选子节点、逐层构造含 `weak_ptr` 的链），随后 `update_hover` 对新旧链做 diff 并整链赋值。同一帧内落在同一控件上的多次移动，除最后一次外的命中测试结果全部被丢弃，其成本与窗口内容无关、随事件频率线性放大。

悬停链的构建还带着 `weak_ptr` 的原子计数与链向量的构造/拷贝，即使指针在同一控件内小幅移动也照付。命中结果在同一布局世代内是确定的：只要指针仍落在链尾控件记录的命中矩形内、且布局/滚动/动画/结构未变，链路必然相同。

## 变更内容

1. **帧内合并移动事件**：事件泵把指针移动缓存为「仅保留最新位置」的待投递项，每帧最多向 `Dispatcher` 投递一次；遇到非移动事件（按下、抬起、滚轮、离开、焦点变化）先冲刷待投递项再处理该事件，保证「先移动、后按下」的顺序不被破坏。合并后的位置取最新样本，不插值、不补发中间点。
2. **命中链复用**：引入单调递增的命中世代号，在布局通过、滚动偏移变化、控件树增删、窗口尺寸/DPI 变化与动画逐帧推进时自增。缓存「世代号 + 链尾控件 + 该控件的命中矩形 + 上次链路」；新位置仍落在矩形内且世代号未变时直接复用链路，否则重新命中测试并回写缓存。
3. **语义边界**：合并只减少同一帧内的移动投递次数，指针的最终位置、按下/抬起目标、悬停进出顺序与点击路由与逐事件处理逐项一致；业务侧数到的移动事件次数会从「每采样一次」变为「每帧至多一次」，此变化写入规格并在迁移说明中标注。

## 验收判据

1. 路由一致性：同一输入序列下，按下/抬起/悬停进入与离开的目标控件、事件先后顺序与改动前逐项相同；悬停链内容（控件序列与各层偏差）逐字段相同。
2. 合并语义可证：新增用例以合成输入在一帧内投递多个不同位置的移动，断言处理次数不超过一、且最终悬停状态与逐事件处理相同；把合并关闭后退回逐事件，该用例必须转红。
3. 复用可证：以布局世代号与链尾矩形为条件，构造「同控件内移动」「跨控件移动」「布局变化后移动到原位置」三类用例，第三类必须重新命中（把复用条件放宽为只看位置时该用例必须转红）。
4. 性能：`PROFILING=ON` 同机同构建，在含大量子节点的滚动列表悬停场景记录改动前后的命中测试耗时与每帧移动处理次数；只接受实测下降，`perf_gates.json` 阈值仅在多轮稳定通过后收紧。
5. 门禁：`ctest --preset ninja-test` 全绿（含全部 `check_*`、`lint`、`format-check`），`aurora_api.json` 无差异。

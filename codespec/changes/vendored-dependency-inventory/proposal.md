## 动机

1. **依赖版本靠人记，存在真实漂移。** 全部 C++ 依赖以整树源码形式置于 `third_party/`，仓库无 `.gitmodules`，无 vcpkg / conan / Cargo / NuGet 等包管理清单，因此包管理器与依赖更新机器人的 C++ 生态都无法识别它们。唯一台账 `THIRD_PARTY_LICENSES.md` 是人工文档：缺 libwebp、wuffs、webview2 三节，stb_image 未写版本，wgpu-native 只写系列；且 libjpeg-turbo 一节指向 `cmake/AuroraImageCodecs.cmake` 的手工副本而非源码树。台账与源码之间没有任何核对。

2. **漏洞核查靠人查，复发无预警。** 上一轮五库升级由人工比对上游版本后发现，其中 mbedTLS 与 SQLite 的旧版本带可由对端证书或握手报文触发的漏洞，恰属内置 TLS 后端输入面。升级完成后 `.github/` 仍无依赖更新配置、无代码扫描、无物料清单、无周期性核查，下一次同类滞后仍只能靠人工发起。

3. **照搬通用方案在此仓是摆设。** 依赖更新机器人对无清单的 vendored 生态不产生任何更新；按包名与版本查询开放漏洞库，对这些 C 库连已知含漏洞的旧版本都返回零命中——库内记录以 Git 提交范围表达，不存在包版本映射；上游发布接口的 tag 命名也不统一（前缀、历史别名、预发布混排）。因此自动红线必须建立在本地可确定性核对的事实上，上游信息只能作为人工复核输入。

4. **一条既有纪律只写在注释里。** `.github/workflows/ci.yml` 的 env 段注释说明折叠标量内的 `#` 行是字面内容、会随环境变量展开进 shell 并注释掉续行；但没有任何强制，且 `release.yml` 的字面块内 `#` 是合法 shell 注释，不能一刀切。

5. **本提案的边界。** 只补台账、门禁、报告与配置；不改任何第三方源码、不改构建开关、不改现有 CI 全量矩阵；新增工作流独立触发，不削弱既有四类全量出口。

## 变更内容

1. 在 `codespec` 下新增机器可读清单，覆盖 `third_party/` 全部顶层项，每条记录名称、版本、权威源文件、解析正则、上游仓库、许可与版本类型；无标准发布号的两项用代理值并写明原因，三段宏拼接的版本用组合规则表达。清单作为唯一真值源，人工台账改为引用它。
2. 在 `tools/check` 下新增版本一致性门禁：逐条以声明的正则从 vendored 源码解析版本并比对，另校验清单非空、字段齐全、名字唯一、源文件存在、正则命中且唯一、版本线内无漂移；新增覆盖守卫，要求清单与 `third_party/` 顶层项双向齐备，堵住新增库漏登；交叉核对 libjpeg-turbo 的 CMake 镜像。全部诊断纯 ASCII，零命中即硬失败。
3. 在 `tools/check` 下新增工作流标量门禁：把注释里的纪律变成判据——只针对 `env:` 下的折叠标量检查 `#` 行与含 `#` 的值，字面块内的 shell 注释不受影响；另做不依赖第三方解析库的结构自检（顶层键、tab 缩进、重复键、零命中守卫），解析器可用时追加完整解析。两枚新门禁在 `cmake/AuroraTests.cmake` 的静态门禁段注册，并同步进现役声明清单，使其受声明核对门禁守护。
4. 在 `tools/sca` 下新增上游版本报告器与物料清单生成器。报告按清单向上游发布接口查询最新版本，按版本线限定并过滤预发布，输出「当前 / 上游最新 / 状态 / 来源」表格；明确声明不可读不等于无漏洞、代理版本必须人工复核、结果只是人工复核输入而非自动漏洞裁决。生成器把同一清单转成 CycloneDX 物料清单，输出确定性字节，代理值以属性保留。
5. 在 `.github` 下新增依赖更新配置，仅覆盖工作流动作这一真实可管的生态；注释写明为何不为 vendored 源码声明包生态。另新增独立审计工作流，按周与手动触发，并在清单或相关脚本变更时随 PR 触发：跑两枚门禁、生成物料清单、产出上游报告写入作业摘要并上传产物。该工作流不改动 `ci.yml`。
6. 补齐根目录第三方许可台账的缺失小节与版本口径（改引清单为版本真值源），并在变更日志的未发布节记一条新增与一条修复。

## 验收判据

1. 新门禁在 `ctest -N` 中真实出现，静态门禁总数由 26 扩到 28 且全绿；现役声明清单同步后声明核对门禁仍绿；入口文档体积门禁不越界。
2. 版本门禁可证伪：把清单任一版本改错、删任一条、把任一正则改成永不命中、清空依赖列表、或直接改动 vendored 源码的版本字面量，五种注入均须转红；还原后全绿。覆盖守卫须能抓出「`third_party/` 存在但清单未登记」的库。
3. 工作流标量门禁可证伪：往 `env:` 折叠标量插入一行 `#` 注释、删除工作流顶层 `jobs:` 键、插入 tab 缩进，三种注入均须转红；对现有 `ci.yml` 与 `release.yml` 的合法 shell 注释零误报，还原后全绿。
4. 物料清单生成器输出可由标准 JSON 解析器读取的 CycloneDX 文档，组件数与清单一致、代理值以属性保留、同一棵树重复生成字节一致；上游报告器在真实网络下产出表格且把不可读项显式标为不可读而非无漏洞。
5. 新增工作流不修改 `ci.yml`，四类全量出口不变；新增门禁为纯静态检查，跨平台构建（含 Emscripten）均可注册与通过；改动文件的增量 lint、格式检查、相关门禁全绿；公共 API 结构无差异。

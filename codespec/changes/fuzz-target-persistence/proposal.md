| 字段 | 值 |
|:---|:---|
| 变更编号 | CHG-073 |
| 提出日期 | 2026-11-08 |
| 当前状态 | 已归档 |
| 关联需求 | 无 |
| 影响面 | 在 `tests/fuzz/` 下新增五个模糊测试目标、一个有效性自证目标与初始种子语料；在 `tools/check/` 下新增判定脚本并给测试目录纪律白名单加一项；新增 `AuroraFuzz.cmake` 构建模块并在根 `CMakeLists.txt` 挂接；新增独立工作流 `fuzz.yml`；回写变更日志、架构、构建选项、编码规范与工具规格。**不补 PNG/JPEG 目标、不注册 CTest、不改现役门禁声明清单、不改 `ci.yml` 的全量矩阵与四类出口、不改公共 API、分层边界、后端矩阵与性能门槛** |

## 动机

1. **输入面缺少长期回归守护。** 上一轮扫描建立的五个覆盖引导目标与种子语料只存在于一次性探针目录，仓库零入库、流水线零覆盖；已落地的不可信输入契约（URI list 出口过滤、流式解压上限按交付路径分派）此后只由定向单测守护，任意字节串输入下的内存错误与未定义行为没有持续发现机制。
2. **一次性探针的「零发现」不可复验。** 探针只跑过单轮短时执行，没有持久化的判定脚本，也没有健康检查。消毒运行时参数一旦退化（例如 UBSan 少了 `halt_on_error`，未定义行为只打印不中断），全部目标仍会正常收尾并给出看似干净的结论，即静默假绿。常驻化必须先把「工具链接上了」变成可判定的前置条件。
3. **补 PNG/JPEG 目标属重复投入。** 扫描报告把这两个目标与常驻化并列为后续动作，但同一份报告在覆盖边界一节明确判定：PNG/GIF/WebP 与 JPEG 走第三方解码器，其缺陷只能靠版本治理，不能靠本仓库的模糊测试；而依赖供应链台账、一致性门禁与周期性上游版本报告已经落地。在本仓库为第三方解码器建目标，还需打开两个默认关闭且宏不导出的图片编解码开关、引入对应的对象库与生成头，把整个图片子系统拉进插桩面，与收益不成比例，故本提案明确不做。
4. **构建口径要求独立变体。** libFuzzer 需要 clang 运行时，gcc 与 MSVC 不提供；覆盖率插桩与 SanitizerCoverage 会互相干扰，且现有覆盖率与地址消毒在配置期互斥。默认构建里 Emscripten、MSVC 与 AppleClang 都会经过测试注册段，因此模糊测试目标必须默认关闭、排除在默认目标之外、由独立构建目录与显式编译器守卫隔离，不能挂进常规测试 runner。
5. **本提案的边界。** 只迁既有五个目标、只入初始种子、只加一条周期性独立作业；不做跨轮持久语料积累、不接外部持续模糊测试服务、不改全量 CI 矩阵、不新增公共 API 与构建产物中的对外符号。

## 变更内容

1. 在 `tests/fuzz/` 下常驻五个目标，分别覆盖 URI list 解码与编码往返、JSON 的文档解析与事件出口、HTTP 响应头与分块装配、WebSocket 解帧状态机、内置 BMP 解码器；沿用「只编译被测路径所需翻译单元」的显式配方，不链接整个库，从而不引入平台后端与第三方解码器。图片与掩码熵源两处链接桩升格为被测面边界声明，在文件头写明其用途与「改为链接整库时须删除」的条件。
2. 新增第六个目标作为消毒链路有效性自证：它故意含一处有符号溢出与一处越界读，只在作业开头带固定种子运行，必须产生崩溃输入与消毒报告；若它不转红，其余五个目标的零发现一律判为无效、作业整体失败。该目标不参与正式覆盖短跑，且在文件头写明严禁链进任何非模糊测试构建。
3. 新增默认关闭的构建开关与 `EXCLUDE_FROM_ALL` 目标聚合，形态照 `AuroraVerify.cmake`；在根 `CMakeLists.txt` 的模块清单与 include 序列挂接。开关打开时要求编译器为 clang，独立构建目录里显式关闭覆盖率与地址消毒并禁用预编译头；编译与链接同参注入 `fuzzer,address,undefined`。
4. 语料只入各目标的初始种子，不入库演化语料。理由是一次性探针的语料目录里混合了已被在线最小化替换的旧文件，报告、日志与磁盘三处计数互不一致；入库前重做一次精简属独立工作，本提案不承诺跨轮积累，只保证每次作业都从可复现的确定性起点出发。
5. 新增独立工作流，按每周定时、手动触发、以及相关路径变更的拉取请求三种方式运行；照供应链审计工作流的编排约束，不修改 `ci.yml`、不动全量矩阵与四类出口。作业用 clang 在独立目录构建六个目标，再由判定脚本统一执行。
6. 新增判定载体脚本而非把判定内联进工作流脚本块：每轮先清理上轮崩溃输入残留；先跑有效性自证并要求其转红，再逐个跑五个正式目标的短时执行；每个目标同时看退出码、崩溃输入文件、消毒报告正文与正常收尾行，任一异常即整体失败。未消毒报告只打印不中断、通过用例的标准错误不被回显等既有假绿陷阱，在脚本注释里写明并由有效性自证兜住。
7. 给测试目录纪律的设施白名单增加 `fuzz` 一项，使新目录不被判为未知类型目录；该项只影响目录纪律，不改任何现役门禁名，故不动现役声明清单与测试注册文件。回写变更日志、架构、构建选项、编码规范与工具规格；不注册 CTest、不新增门禁声明。

## 验收判据

1. 六个目标在独立 clang 构建下全部编出；默认配置与 Emscripten、Windows、macOS 三套配置都不出现这些目标，主编译数据库零差异。
2. 有效性自证可证伪：固定种子必须产生崩溃输入与消毒报告；把消毒运行时的中断开关去掉、或把自证目标换成不触发缺陷的空实现，判据须转为「链路无效」并让作业失败，还原后转绿。
3. 判定脚本可证伪：注入伪造的崩溃输入、非零退出码、缺失正常收尾行三类变异均须转红；预置的陈旧崩溃输入必须被每轮清理；未设报告目录须硬失败；还原后全绿。
4. 正式短跑在修复态下五个目标各运行九十秒、输入长度上限四千零九十六字节，零崩溃输入且每份日志以正常收尾行结束；判定脚本输出汇总通过。
5. 静态门禁全绿、格式检查通过、改动文件的增量 lint 无新增告警；工作流可由标准解析器完整读入且触发条件逐项可核；提案契约、编号连续性与回写落点路径存在性自查通过；公共 API 结构无差异。

| 字段 | 值 |
|:---|:---|
| 变更编号 | CHG-082 |
| 提出日期 | 2026-11-17 |
| 当前状态 | 已提议 |
| 关联需求 | 无 |
| 影响面 | `src/aurora/render/painter.cpp`（`begin` 的基底清零）、`include/aurora/render/painter.h`（私有成员与内部访问钩子）、`src/aurora/engine/`（帧绘制入口判定不透明覆盖）、各窗口后端绘制入口；**公共 API 签名与 `aurora_api.json` 无差异**，`Painter` 仅增私有成员 |

## 动机

`Painter::begin` 每帧对整块帧缓冲执行一次全零填充。2560×1440 的窗口即约 14.7 MB 写入，与窗口内容无关、与是否全屏重绘无关，纯属带宽开销；大窗口与高 DPI 下这一项固定成本可观，且与紧随其后的全屏背景填充重复写入同一片内存。

绝大多数窗口每帧都以不透明根背景铺满整窗，清零写入的每个字节随后都会被覆盖。只有在根背景半透明、窗口透明/圆角外形、或本帧只重绘脏区（需保留上帧像素基线）时，清零才是必需的。

## 变更内容

1. **判定条件**：帧绘制入口在「根背景色 alpha 为 255、且覆盖整个逻辑视口、且当前窗口不是透明/异形外形、且本帧为整帧重绘而非脏区补绘」四条同时成立时，标记本帧为不透明全覆盖。
2. **清零策略**：为不透明全覆盖帧跳过整缓冲清零；其余情况维持现有全零基底。帧缓冲尺寸变化、首次分配、`set_scale` 变更后的首帧一律强制清零，避免把上一尺寸的残留像素带入新缓冲。
3. **接口形态**：不新增公共重载、不改 `begin` 签名；通过 `Painter` 的私有成员加内部访问钩子传递策略，钩子只对引擎与窗口后端可见。公共头新增内容仅为私有成员与友元声明，`aurora_api.json` 不变。
4. **安全网**：不透明判定处于未启用或任一条件不成立时，行为与现状逐位相同；不引入「本帧未覆盖区域保留上帧像素」的新语义。

## 验收判据

1. 像素一致：所有既有 golden 与 `utest_painter` / `utest_offscreen` 场景逐位 0 差异；新增「不透明根背景全屏绘制」场景，在清零与跳清零两条路径下输出逐字节相同。
2. 必须清零的反例：根背景 alpha < 255、异形窗口、脏区补绘三类场景各一条用例，断言输出与全零基底一致（把跳清零条件放宽后这些用例必须转红）。
3. 尺寸变化：改变 `begin` 尺寸或 `set_scale` 后的首帧，断言无旧尺寸残留（跳过强制清零时该用例必须转红）。
4. 性能：`PROFILING=ON` 同机同构建记录 `clear` 分项与帧总耗时的前后值；只接受实测下降，`perf_gates.json` 仅在多轮稳定通过后收紧。
5. 门禁：`ctest --preset ninja-test` 全绿（含全部 `check_*`、`lint`、`format-check`），`aurora_api.json` 无差异。

## 回写落点

- `codespec/specification/03-layout-render.md`：补帧基底契约——清零为默认、不透明全覆盖帧可跳过、强制清零的触发条件。
- `codespec/ARCHITECTURE.md`：渲染章节补「帧基底与脏区重绘」的边界，明确跳过清零不改变任何可见像素。
- `codespec/BUILD_OPTIONS.md`：若以缓存变量或 feature 宏控制该路径，在此登记开关名与默认值。

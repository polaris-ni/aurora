## 动机

`Painter::begin` 每帧对整块帧缓冲执行一次全零填充。2560×1440 的窗口即约 14.7 MB 写入，与窗口内容无关、与是否全屏重绘无关，纯属带宽开销；大窗口与高 DPI 下这一项固定成本可观，且与紧随其后的全屏背景填充重复写入同一片内存。

绝大多数窗口每帧都以不透明底色铺满整窗，清零写入的每个字节随后都会被覆盖。只有在底色半透明（含透明窗口的逐像素外形）或本帧只重绘脏区（需保留上帧像素基线）时，清零才是必需的。

**范围核实**：本仓只有 `D3D11Surface` 与 `WgpuWin32Surface` 每帧无条件 `begin`；`Win32` / `GLFW` / `X11` / `macOS` / `Wayland` 仅在尺寸变化时 `begin`（本就低频，且尺寸变化强制清零），`Headless` 的底色全透明。故只有前两个后端接入本优化。

## 变更内容

1. **判定条件**：判定落在真正铺底色的那一层（`begin_frame`）——「底色 alpha 为 255、且铺满整块缓冲、且当前不在显示列表录制态」同时成立时，本帧可跳过清零。原提案的「窗口非透明/异形」并入底色 alpha（透明窗口与 CSD 外形由 `present` 与系统合成处理，帧基底仍是不透明铺满）；「整帧重绘而非脏区补绘」自然成立，因为脏区路径根本不经过 `begin`。
2. **清零策略**：可跳过时保留既有像素（随后被不透明底色逐字节覆盖）；其余情况维持现有全零基底。帧缓冲尺寸变化、首次分配、`set_scale` 变更后的首帧一律强制清零，避免把上一尺寸的残留像素带入新缓冲；录制态强制清零，因为此时底色只入命令流、不落像素。
3. **接口形态**：不新增公共重载、不改 `begin` 签名；通过 `Painter` 的私有成员加内部访问钩子传递策略，钩子定义在内部头 `src/aurora/render/detail/frame_base.h`，只对库实现与测试可见。公共头新增内容仅为私有成员与友元声明，`aurora_api.json` 不变。
4. **安全网**：不透明判定处于未启用或任一条件不成立时，行为与现状逐位相同；不引入「本帧未覆盖区域保留上帧像素」的新语义。

## 验收判据

1. 像素一致：所有既有 golden 与 `utest_painter` / `utest_offscreen` 场景逐位 0 差异；新增「不透明底色全屏绘制」场景，在清零与跳清零两条路径下输出逐字节相同。
2. 必须清零的反例：底色 alpha < 255、底色未铺满整块（异形/半覆盖外形）、显示列表录制态各一条用例；另以「跳清零条件被放宽」为对照，这些用例必须转红。脏区补绘路径不经过 `begin`，由既有 `itest_dirty_clip_paint*` / `itest_partial_repaint_bg` 覆盖。
3. 尺寸变化：改变 `begin` 尺寸或 `set_scale` 后的首帧，断言无旧尺寸残留（跳过强制清零时该用例必须转红）。
4. 性能：`D3D11` / `Wgpu` 后端才有固定开销可省；本机无对应窗口基准条件，故以逐字节一致性与逻辑用例作为验收，`perf_gates.json` 不收紧。
5. 门禁：`ctest --preset ninja-test` 全绿（含全部 `check_*`、`lint`、`format-check`），`aurora_api.json` 无差异。

## 回写落点

- `codespec/specification/03-layout-render.md`：补帧基底契约——清零为默认、不透明全覆盖帧可跳过、强制清零的触发条件。
- `codespec/ARCHITECTURE.md`：渲染章节补「帧基底与脏区重绘」的边界，明确跳过清零不改变任何可见像素。

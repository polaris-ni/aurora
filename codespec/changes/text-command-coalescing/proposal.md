| 字段 | 值 |

| 提出日期 | 2026-11-17 |

## 动机

布局稳定后，每帧的绘制基本是显示列表的整段回放。表格单元格、终端网格、标签密集的工具栏会在列表里留下大量相邻的 `DrawText` 命令：每次回放一次都要重新解析字体面（族名散列、字重/字号查表）、重算像素尺寸与行高，再逐行发射字形。同一批相邻文本往往共享字体、字号、颜色与摆放基线，这些每次调用的固定开销被重复支付，与文本长度无关、与控件数量线性相关。

`Painter` 已提供 `draw_text_runs` 批量入口，其契约明确「与逐个 `draw_text` 逐位一致」，但回放路径没有使用它。

## 变更内容

1. **相邻合并**：回放循环在遇到 `DrawText` 时向后探查紧随其后的同类命令，直到遇到不满足条件的命令为止。合并条件为：字体族、字重、字号、颜色、排版选项、设备像素比例全部相同，且乱序/方向等排版字段一致。
2. **保持次序**：只合并列表中**连续**的命令，不重排、不跨命令移动，因此覆盖顺序与裁剪栈作用范围不变。
3. **回放中嵌套录制**：合并后调用 `draw_text_runs`，其录制态按片段各落一条 `DrawText`，与原逐条回放产出的命令序列逐条相同。
4. **退化路径**：单个 `DrawText`、字体或颜色不同、跨裁剪命令的场合保持逐条回放，行为与现状完全一致。

## 验收判据

1. 逐位一致：`utest_painter` / `utest_painter_primitives` / `utest_offscreen` 与全部 golden 场景逐位 0 差异；新增场景以「同一字体连续的多个文本命令」构造，断言合并回放与逐条回放的像素缓冲逐字节相同。
2. 不合并的反例：字体或颜色不同、两个文本命令之间夹有矩形/裁剪命令时，断言仍逐条回放（把合并条件放宽为忽略颜色后该用例必须转红）。
3. 命令序列不变：以录制态回放，断言产出命令序列与原序列逐条相同（类型、顺序、文本与坐标字段一致）。
4. 性能：`PROFILING=ON` 同机同构建，在文本密集场景记录 `text` 分项与每帧字体面解析次数的前后值；只接受实测下降，`perf_gates.json` 仅在多轮稳定通过后收紧。
5. 门禁：`ctest --preset ninja-test` 全绿（含全部 `check_*`、`lint`、`format-check`），`aurora_api.json` 无差异。

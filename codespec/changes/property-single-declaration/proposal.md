## 动机

> 本提案面向**不读源码**的审查者。动机第 1–3 条把现状描述清楚（数字与测量口径均可就地复核），第 4–7 条给出该现状直接产生的四处缺陷，第 8 条说明为什么必须一起改，第 9 条给出本轮新增的语言层事实——它决定了本提案最终形态的边界，并把早期几种写法排除在外。

1. **背景 · 一个属性的事实散在四个手写地点**。Aurora 的控件属性以「公有数据成员」交付：每个控件声明一个 `XxxProps` 聚合结构（字段带声明处默认值），控件本体写作 `class Xxx : public LeafWidget, public XxxProps` —— Props 的字段就是控件自身的公有字段，不再用私有 `m_*` 重复声明（这是 `codespec/CODING_STANDARDS.md` §11.1 为「三种构建形态语义等价」定的机制）。实测：18 个 `XxxProps` 声明、17 处公有继承（`TextInput` 声明了 `TextInputProps` 但本体未继承）、`aurora_api.json` 收录 76 控件 / 639 属性。除① 结构体字段与声明处默认值本身，每个属性还要在三个地点各表达一次：② `describe_static()` 里的 `PropDescriptor` 条目（名称 / 类型 / 默认值显示串 / 枚举 / 上下界 / `required` / `json_type` / `note`），供 LSP、MCP、CLI、`validate_ui`、`codegen`、Inspector 消费；③ `serialize_props(Json&)` 里一条「取值并写入键」分支；④ `deserialize_props(const Json&)` 里一条「查键并写回字段」分支。实测出现次数：`describe_static` 255 处（74 文件）、`serialize_props` 349 处（77 文件）、`deserialize_props` 144 处（60 文件）；描述符里手写 `enum_values` 102 处、手写 `min_value` / `max_value` 117 处。四份副本之间没有任何相互校验 —— 一份写错、漏写、或改名不同步，编译与测试都不会响。JSON 侧已被同一根因咬过：属性事实曾在 `aurora_api.json` 里存了四份并互相漂移，事后才收口为单一 `props` 数组；本提案处理的是**代码侧那份尚未收口的同源重复**。

2. **背景 · 刷新有两条并行通道，其中一条是手写的**。通道甲是**手标脏**：写属性时挨个调 `mark_needs_layout()` / `mark_needs_paint()`（两者都是 `Widget` 的公开入口）。实测 411 处调用点（`mark_needs_layout()` 132 处、`mark_needs_paint()` 321 处出现总数）。`mark_needs_paint()` 的动作是三合一：置本控件绘制脏位、沿布局父链失效祖先 Display List 缓存、请求一次重绘帧；Display List 缓存默认开启，所以**漏掉这一句的写操作既不触发重绘、也让祖先继续回放旧命令**。通道乙是**信号接线**：`ReadOnlyState<T>` 型属性经控件覆盖 `collect_signals(StateSink&)` 登记，基类按登记逐个订阅，任一来源变更时回调 `on_signal_dirty()`（缺省实现为「标布局脏 + 标绘制脏」）。通道乙不需要手写标脏，但粒度粗：`StateSink` 只登记来源**身份**（其契约明文「采集只登记来源身份，不附加属性名或作用域标签」），框架无法知道「变的是绘制档还是几何档」，只能取并集一律双标；实测 `collect_signals(StateSink` 62 处（50 文件），而 `on_signal_dirty()` 的覆盖**全库只有一处**（`Provider`，为换值后追加一次整子树缓存清零）。结论：一条本应数据驱动的语义，现在同时以「每控件手写虚函数覆盖」和「每 setter 手写标脏」两种形态存在，后者是 411 处、会漂移的那一条。

3. **背景 · 主题相关默认值靠一套四步仪式手工复刻**。`Theme` 现由色角色集（`ColorRoles`）、排版 15 档（`TypeScale`）、窗口装饰配色、明暗档与类型安全扩展注册表组成 —— **没有任何形状 / 间距令牌**。于是「颜色跟随主题」这一类属性只能这样写：字段声明为 `std::optional<T>`（`include/aurora/widget` 内 `std::optional<` 218 处）、取值时才回退（`inherit_theme(` 68 处 / 36 文件）、序列化时「未设置就不写这个键」（widget 头文件内 `.has_value()` 173 处）、描述符里把默认值写成**显示串** `"theme.primary"` 而非可求值的值（`include/aurora/widget` 内 `"theme.` 字面量 50 处 / 22 文件），JSON 侧再靠 `default_expr` 单独承载这一形态（schema 现收 77 条，`default` 条目 558 条）。这套仪式目前是纯手工的：每加一个主题敏感属性就要四步各写一遍，且没有任何机制保证四步说的是同一件事。

4. **缺陷一 · 手写标脏已经在漏，且漏在用户最常调的属性上**。以 `Button` 为样本：表征 UI 的链式 setter 中只有 `set_label`（含两个常量重载）、`set_background_source`（含转发的 `background`）与 `set_enabled` 标脏；其余 —— `text_color`、`set_corner_radius`、`set_padding`、`set_hover_color`、`set_pressed_color`、`set_border`、`set_disabled_colors`、`set_min_size` —— **只写字段、不标任何脏**。按第 2 条的机制，挂载后调用这些 setter：颜色改了不上屏、圆角改了不上屏、内边距与最小尺寸改了既不重排也不重绘，直到同帧内别的事件（如指针进入触发的 `on_hover_change`）顺带把该子树标脏才偶然刷新。同一批键在 `deserialize_props` 里连这套不完整的纪律都没有：除 `label` / `color` 两键转手走 setter 外，其余键一律**直接写字段、函数体内不做任何标脏** —— 于是 Inspector 的单属性热回写（`set_widget_prop`，其文档因此只能写「可能标脏重绘」）对这些键同样不刷新。漏标不是 Button 独有，而是 411 处手写的必然分布 —— 每新增一个 setter，都要靠人记得「这是绘制档还是几何档」。

5. **缺陷二 · 形态三在类型层根本拦不住，来源型属性还会句柄分裂**。C++ 没有属性语法，对公有数据成员的赋值观察不到、拦不住 —— 这是语言事实，不是实现疏忽。后果分两种：值型属性（如 `corner_radius`）`btn.corner_radius = 4.0F;` 改的就是绘制读的存储，于是「值改了但没人标脏」= 静默旧画面；来源型属性更严重 —— `Button` 为换源纪律把 `label` / `color` 各复制了一份私有镜像（`label_` / `color_`，公有字段与镜像是两个句柄对象，共享同一个来源节点），`ReadOnlyState` 的赋值是**换绑句柄**而非改源，于是 `btn.color = other_source;` 只改了那个不再被读的公有句柄，控件与 `collect_signals` 仍固定旧源 —— 这次赋值**永久无效**，而且完全编译通过、无任何诊断。项目已经验证过唯一零成本的拦截形态：`Button` 给 `label` 提供了同名只读访问器 `label()`，派生作用域的函数名遮蔽基类字段，使 `btn.label = x` 直接编译失败并点名「这是成员函数」；但这一手法目前**只用在一个字段上**，其余数百个字段仍是可静默误写的公有成员。业界同样如此：没有任何主流框架把「可变的公有数据成员」当响应式的写面 —— 拦截一律放在访问器（Qt 属性 / Setter、Swift `didSet`、Kotlin 委托属性、JS `Proxy`），或者干脆不给你可变字段（Flutter 全 immutable + 重建，ImGui 每帧重建）。

6. **缺陷三 · 表征性默认值无法跟随主题，且没有可扩展的落点**。`corner_radius = 6.0F`、`padding = {12, 6, 12, 6}`、各图表 `dot_radius = 2.0F / 3.0F / 4.0F` 这类**外观与几何常量**现在硬编码在字段声明处；换 `ThemeScope` 换肤时颜色全变、圆角与间距纹丝不动。要修就得先给 `Theme` 加形状 / 间距令牌组，而每加一个令牌敏感属性，就要把第 3 条那套四步手工仪式原样再写一遍 —— 现状既没有令牌的存放处，也没有「默认值来自令牌」的机器可读表达（描述符只能存显示串）。本变更的**主题档**消费端限于**与档位同型的标量属性**（圆角档 → `corner_radius` / `dot_radius`，间距档 → `gap` 一类），四边结构的 `EdgeInsets` 属性不在内，理由见变更内容第 6 条；但按第 6 条的强制回落规则，它仍必须有回落点 —— 用的是**库内默认提供者**形态而非主题档，于是「有无回落」不再是属性之间的差异，差异只在回落到活令牌还是落到常量。

7. **缺陷四 · 三形态等价性目前是「靠约定保证」的弱承诺**。`codespec/CODING_STANDARDS.md` §11.1 声明形态一（链式 setter）≡ 形态二（`*Props` 具名聚合）≡ 形态三（逐行赋值），等价性由「控件继承 Props、字段即存储」保证。但按第 5 条，来源型属性的形态三在语义上并不等价（公有句柄与私有镜像分叉），值型属性的形态三在效果上不等价（缺标脏），文档承诺与真实行为已经背离 —— 对以「AI 易生成、生成即可信」为定位的库，这是最坏的一类缺口：模型按文档写出的代码能编译、不报错、画错画面。

8. **根因是同一个，所以必须一起改**。三件事的共同根：**属性是数据，却按代码分散表达** —— 名称与默认值在结构体、元数据在描述符条目、读写在两条分支、刷新语义在 411 处手写调用、主题回退在取值点的一次 `value_or`。只要「一条属性的事实」仍散在六个手写地点，任何局部修补（例如给 Button 补 8 处 `mark_needs_paint()`）都只是把漂移的下一次发生往后推。把「属性」重新表达成**一条住在 `XxxProps` 类里的完整声明**（字段私有、档位与约束写在同一张权威表的行上、读写件与发射面全部由该行派生），机制实现**每档语义全库只写一份**（`AbstractProps<Derived>`，零虚函数），控件侧只剩「公有继承 + 四行转调 + 构造尾部一次 `bind`（第 7 条）」，则缺陷一、二、四在结构上消失，缺陷三获得唯一说得清的落点（行上的令牌引用 + `Theme` 的令牌组）。三项已锁定裁决作为本提案的前提：① 进响应层的是「可配置的、表征 UI 的属性」，逻辑类（`on_click`、`on_scroll_changed` 等回调，widget 头文件内 `std::function<` 142 处）不进；② 刷新语义数据驱动、由表行给定，不逐控件写虚函数覆盖 —— 全库唯一一处覆盖恰好只表达一个传播位，而虚函数是「替换语义」，不可枚举也不可审计；③ 属性写入面收口到访问器，公有字段退出公共 API。

9. **本轮新增的语言层事实（探针实测，见「变更内容」末附录），它把早期几种写法排除在外**。其一，**声明了任何 virtual 的类不是聚合**，「Props 带虚函数 + 聚合指定初始化器」两者不能共存（探针 9：两编译器同报非聚合）—— 于是「Props 层零虚函数、多态留在 Widget 层」是硬约束而非风格选择。其二，**在自身类体内取本类私有成员的指针，写成 `static constexpr` 数据成员会编译失败，写成 `static constexpr` 成员函数才成立**（探针 1 / 2 / 3：字段声明在其后的数据成员形态被三套编译器一致拒为「不是成员」，把字段提前则通过，函数形态无论位置都通过）—— 权威表必须是函数形态的行，否则要么把私有字段顶到类最前面（与「公共 API 在前」的既有排版纪律冲突），要么放弃 constexpr。其三，**指定初始化器不能指名继承来的成员**（探针 8），而「公有字段 + 继承 Props」的形态二恰好依赖它 —— 即便退让到公有字段，形态二也已比现状窄一格。其四，**属性名与换源句柄可以同名过载**（探针 10 通过），但**字符串型属性的字面量调用必须保留便利重载**（探针 11 在三套编译器上一致报「无匹配函数」；今天 `include/aurora/widget/button.h` 的三个 `set_label` 重载正是这条规则的既存实现）。其五，值型属性的**全默认参数构造**不可行：默认实参只能从尾部省略，且相邻同型参数（`Button` 有 5 个连续可选色字段、`TextProps` 16 字段）静默错位 —— 那是第 5 条缺陷二的同类且更隐蔽，本轮不予采纳（该结论无探针，是语言规则的直接推论，附录只收有编译证据的条目）。

## 变更内容

0. **定稿形态一览**。属性对象就是 `XxxProps` **类**：字段私有、读写件与权威表同住这个类、零虚函数（CRTP 基类提供机制）；控件**继续公有继承它**（继承面即公共 setter / getter 面，控件侧零转发样板）；发射面四行转调基类通用实现；构造面为链式 `XxxProps().set_a(x)`；宿主引用经 `bind(host)` 建立、由 `Widget` 的移动面单点重绑（第 7 条：`resubscribe_signals()` 是 `Widget` 的 protected 成员，属性面取不到，重订阅经 `Widget` 装入链接位的库内 thunk 走，不外放可见性）。机制一份、真源一处、访问器由表项生成、字段不可直写 —— 第 5 条的静默旁路从「门禁拦」升级为「编译拦」，连控件自己的类内代码也只能走访问器。**回落点强制、位与值同位**：每个属性行都有回落点 `.fallback(...)`（活令牌 / 常量值 / 库内默认提供者 / 派生提供者，第 6 条），于是**可空 ⇔ 非必填** —— 不再按「这行碰巧有没有令牌」分叉；`std::optional` 只存在于私有字段，公共签名一律裸 `T`；**公共读面每行恰一件** —— 回落点是常量的行只有 `x()`（该形态下它就是生效值），回落点随作用域变的行只有 `x(ctx)`，二者不再同名共存（第 2 条）；撤表态是**全库一份公共件 `clear(row)`**，不逐属性生成 `reset_x()`；「是否来源型」由字段形状声明，行上**不写** `.source()` 旁注（第 1 条末注）。换肤时「系统给的」与「用户给的」由表态位机械判读（库内 `present(row)` + schema 的 `overridden`），不靠值猜。

**本轮第二次收窄（Button 全量重写探针驱动，与上一条提交的「同名两件」口径对撞）**。探针按上一轮口径把 `Button` 的 15 个属性整面重写并跑通后清点：公共面 54 个名字 / 64 个成员函数，其中 45 个是与属性键一一对应的规则件（`x_row()` / `set_x` / `x`），另外 9 个是表外名字（`rows` / `bind` / `props_descriptor` / `props_source_bits` / 组合便利写件 `set_border` / 合成读件 `font` / 两枚句柄读件 `label_source` `color_source` / 唯一的动作件 `clear`）—— 模型从键名 `color` 推不出这 9 个的存在，「面小」是假、猜不到是真。据此三条动作：① 发射与接线机器（`bind` 及 descriptor 发射件）退出公共面转 protected 或归库内，`props_source_bits` 是探针自证件、不发；② 表外词汇糖一律不发（`font()`、`set_border()` 与现状的 `set_min_size()` / `set_disabled_colors()`、`x_source()` 一类句柄读件），组装聚合 `Font` 归控件私有、组合便利写件改链式两行表态；③ 读面改为**每行恰一件**，同名两读件的「选错不报错」歧义面归零。收窄后公共面 47 个名字 / 51 个成员函数：45 个规则件 + `rows()` + `clear(row)`，唯一的表外动作件仍是 `clear`，其余 **7 个**清零。两组数字都是实测（探针 14 与 18 是同一份 Button 的两个形态，口径＝`Props` 可见公共面：`AbstractProps` 的公共件 + `ButtonProps` 声明面）：收窄前 54 = 50 声明名 + `bind` / `props_descriptor` / `props_source_bits` / `clear` 四件，64 = 60 条目 + 4；收窄后 47 = 46 声明名（`ButtonProps` 实测）+ `clear`，51 = 50 + 1，差额即删掉的 6 枚同名无参件、2 枚 `*_source()`、合成读件 `font()`、组合写件 `set_border()` 四枚声明名与 6 枚无参条目，另 3 件（`bind` / `props_descriptor` / `props_source_bits`）按 ① 转 protected 后不计入。名字侧的构成也可逐条推回：47 = 15 行 + 15 写件名 + 15 读件名（每行恰一名）+ `rows` + `clear`；51 = 47 + `set_label` 的四枚过载（+3）+ `set_color` 的两枚（+1）。剩下的 30 个手写转发件改由**逐属性宏 `AURORA_PROP(<词根>)` 生成**（口径变化见第 10 条）：公共面名字数不变，手写源码与注释成本减半，且访问器与表同源、不可能漂移。

1. **单一声明点：`XxxProps` 类 + 每属性一行的权威表（函数形态的行）**。以 `Button` 为样本（15 个属性，此处示 10 行，其余同型）：

    ```cpp
    // include/aurora/widget/button.h
    class ButtonProps : public AbstractProps<ButtonProps> {   // 零虚函数（CRTP）
      public:
        // ---- 权威表：键名 / 成员指针 / 档位 / 约束 / 回落点只在这里各出现一次 ----
        // 每行二选一：`.fallback(...)`（回落点，三形之一，见第 6 条）或 `.required()`（回落点即自身）。
        static constexpr auto label_row() { return prop_row<&ButtonProps::label_>("label").layout().required(); }
        static constexpr auto color_row() { return prop_row<&ButtonProps::color_>("color").paint()
            .fallback<&ColorRoles::primary>().note("Background color"); }          // 活令牌档：形态是模板实参
        static constexpr auto on_color_row() { return prop_row<&ButtonProps::on_color_>("on_color").paint()
            .fallback<&ColorRoles::on_primary>(); }
        static constexpr auto font_size_row() { return prop_row<&ButtonProps::font_size_>("font_size").paint()
            .json_type("number").bounds(0.0F, 4096.0F).fallback(14.0F); }          // 常量档：字面量类型给值形态
        static constexpr auto corner_radius_row() { return prop_row<&ButtonProps::corner_radius_>("corner_radius")
            .paint().bounds(0.0F, 1.0e7F).fallback<&ShapeScale::medium>().note("Corner radius (dp)"); }
        static constexpr auto padding_row() { return prop_row<&ButtonProps::padding_>("padding").layout()
            .fallback(&ButtonProps::padding_default); }                            // 常量档：提供者形态
        static constexpr auto enabled_row() { return prop_row<&ButtonProps::enabled_>("enabled").paint()
            .fallback(true); }
        static constexpr auto hover_color_row() { return prop_row<&ButtonProps::hover_color_>("hover_color").paint()
            .fallback(&ButtonProps::hover_default).shows("auto"); }                // 派生档：要读 ctx 与他行现值
        static constexpr auto border_color_row() { return prop_row<&ButtonProps::border_color_>("border_color")
            .paint().fallback(Color{0, 0, 0, 0}).requires_prop("border_width"); }  // `.requires` 撞关键字，故 `.requires_prop`
        static constexpr auto border_width_row() { return prop_row<&ButtonProps::border_width_>("border_width")
            .paint().bounds(0.0F, 1.0e7F).fallback(0.0F); }

        // ---- 表本体：只列行名，不再重复键名与成员指针 ----
        static constexpr auto rows() {
            return make_prop_rows(label_row(), color_row(), on_color_row(), font_size_row(), corner_radius_row(),
                                  padding_row(), enabled_row(), hover_color_row(), border_color_row(),
                                  border_width_row());
        }

        // ---- 写面：实参一律裸 T；一次写入即「表态」，未表态才轮到回落点 ----
        auto set_label(LocalizedString v) -> ButtonProps & { return assign(label_row(), std::move(v)); }
        auto set_label(const std::string &v) -> ButtonProps & { return set_label(LocalizedString{v}); }
        auto set_label(const char *v) -> ButtonProps & { return set_label(LocalizedString{std::string{v}}); }
        auto set_label(ReadOnlyState<LocalizedString> v) -> ButtonProps & { return rebind(label_row(), std::move(v)); }
        auto set_color(Color v) -> ButtonProps & { return assign(color_row(), v); }              // 装入自有常量源
        auto set_color(ReadOnlyState<Color> v) -> ButtonProps & { return rebind(color_row(), std::move(v)); }
        auto set_on_color(Color v) -> ButtonProps & { return assign(on_color_row(), v); }
        auto set_font_size(float v) -> ButtonProps & { return assign(font_size_row(), v); }
        auto set_corner_radius(float v) -> ButtonProps & { return assign(corner_radius_row(), v); }
        auto set_padding(EdgeInsets v) -> ButtonProps & { return assign(padding_row(), v); }
        auto set_enabled(bool v) -> ButtonProps & { return assign(enabled_row(), v); }
        auto set_hover_color(Color v) -> ButtonProps & { return assign(hover_color_row(), v); }
        auto set_border_color(Color v) -> ButtonProps & { return assign(border_color_row(), v); }
        auto set_border_width(float v) -> ButtonProps & { return assign(border_width_row(), v); }
        // 描边按钮 = 两行各表一次态：`set_border_color(c).set_border_width(w)`。组合便利写件（现状
        // `set_border` / `set_min_size` / `set_disabled_colors`）与合成读件（`font()`）一律不发 ——
        // 它们是表外名字，不进 descriptor、不进序列化、不计入覆盖率，模型无法从属性键枚举（第 1 条末注）。

        // ---- 撤表态：不逐属性发名字。公共面是全库一份的 AbstractProps::clear(row)，
        //      写法 `props.clear(ButtonProps::color_row())`；必填行（label_row()）传入即编译期拒绝。

        // ---- 读面：每行恰一件，形态由该行回落点是否随作用域变唯一决定（不存在同名重载集）----
        [[nodiscard]] auto label() const -> LocalizedString { return get(label_row()); }
        [[nodiscard]] auto font_size() const -> float { return stated(font_size_row()); }
        [[nodiscard]] auto padding() const -> EdgeInsets { return stated(padding_row()); }
        [[nodiscard]] auto enabled() const -> bool { return stated(enabled_row()); }
        [[nodiscard]] auto border_color() const -> Color { return stated(border_color_row()); }
        [[nodiscard]] auto border_width() const -> float { return stated(border_width_row()); }
        // 回落点随作用域变的两类行（活令牌档 + 派生档）只有带 ctx 的一件，无参件不发：
        [[nodiscard]] auto color(const BuildContext &ctx) const -> Color { return resolve(color_row(), ctx); }
        [[nodiscard]] auto on_color(const BuildContext &ctx) const -> Color { return resolve(on_color_row(), ctx); }
        [[nodiscard]] auto corner_radius(const BuildContext &ctx) const -> float {
            return resolve(corner_radius_row(), ctx);
        }
        [[nodiscard]] auto hover_color(const BuildContext &ctx) const -> Color {
            return resolve(hover_color_row(), ctx);
        }
        // 句柄读件（现状 `label_source()` / `background_source()`）不发：实测零消费者（第 2 条末注）。

      private:
        // 常量档的两种写法：literal 类型直接给值（未测项其一的结案），含 `std::string` 的类型（`Font`
        // 一类）给静态提供者 —— 值 NTTP 对它不成立。
        [[nodiscard]] static auto padding_default() -> EdgeInsets {
            return EdgeInsets{.left = 12.0F, .top = 6.0F, .right = 12.0F, .bottom = 6.0F};
        }
        // 派生档的回落点：要读当前作用域下他行的生效值（hover = ctx 下的背景调暗）。
        [[nodiscard]] static auto hover_default(const ButtonProps &self, const BuildContext &ctx) -> Color {
            return darken(self.color(ctx), 0.92F);
        }

        // 存储层：**可空 ⇔ 非必填**（第 6 条强制回落后不再按「有无令牌」分叉），且 `std::optional`
        // 只活在这里，不出现在任何公共签名上。「是否来源型」不再写成行上的旁注，只由这里的字段形状声明。
        ReadOnlyState<LocalizedString> label_;            ///< 必填件 + 来源型：不可空、`clear` 拒它、回落点即自身
        std::optional<ReadOnlyState<Color>> color_;       ///< 来源型：句柄整体可空（单一空态）+ 活令牌回落
        std::optional<Color> on_color_;                   ///< 值型 + 活令牌回落
        std::optional<float> font_size_;                  ///< 一属性一字段一表态位（投影件 `.project` 退役，见第 1 条末注）
        std::optional<float> corner_radius_;              ///< 值型 + 活令牌回落
        std::optional<EdgeInsets> padding_;               ///< 不同型属性也强制回落，落到库内默认提供者
        std::optional<bool> enabled_;                     ///< 值型 + 常量回落
        std::optional<Color> hover_color_;                ///< 值型 + 派生回落（故只有 `hover_color(ctx)`）
        std::optional<Color> border_color_;               ///< 值型 + 常量回落（透明 = 无边框）
        std::optional<float> border_width_;               ///< 值型 + 常量回落
        // ... pressed_color_ / disabled_color_ / disabled_text_color_ / min_width_ / min_height_
    };

    class Button : public LeafWidget, public ButtonProps {   // 公有继承保留（现状机制原样）
      public:
        explicit Button(ButtonProps p = ButtonProps()) : LeafWidget(), ButtonProps(std::move(p)) {
            bind(*this);   // 第 7 条：重订阅经 Widget 装入链接位的库内 thunk（属性面取不到那个 protected 件）
        }

        auto collect_signals(StateSink &out) -> void override { collect_prop_sources(out); }  // 一行
        [[nodiscard]] static auto describe_static() -> WidgetDescriptor { return props_descriptor<ButtonProps>("Button"); }
        auto serialize_props(Json &props) const -> void override { props_serialize(props); }
        auto deserialize_props(const Json &props) -> void override { props_deserialize(props); }

      protected:
        // 行为代码：作用域依赖回落的行一律读 x(ctx)（那是该行唯一的读件）；常量回落行读 x() 即生效值。
        auto on_paint(Painter &p, const Rect &bounds, const BuildContext &ctx) -> void override;
    };
    ```

    - 行构造器 `prop_row<&P::f>("key")` 把成员指针与键名钉在**同一个实参位**，漂移距离为零；链式旁注只在**不可派生**时出现：`.layout()` / `.paint()`（档位）、`.fallback(...)`（**回落点，必填件除外每行必备**，三形见第 6 条）、`.bounds(min, max)`、`.json_type("…")`、`.note("…")`、`.requires_prop("other_key")`（跨字段关系，如 `border_color` 依赖 `border_width`；**这个名字不能写作 `.requires`** —— `requires` 是 C++20 关键字，成员函数取不了它）、`.shows("…")`（**降级为显示别名**：默认串一律由回落点派生，仅当回落点的值不可格式化时才手写覆盖）。**`.source()` 旁注本轮退役**：「是否来源型」在字段形状（`ReadOnlyState<T>` / `std::optional<ReadOnlyState<T>>`）里已经说过一次，行上再写一遍正是本提案要消灭的「同一事实两处住处」，所以 schema 的 `source` 位改由字段类型推导（第 3 条），表上不再出现这个字。`.required()` 与 `.fallback(...)` **二选一且必选其一** —— `.required()` 是「回落点即自身」的退化写法（字段不可空、公共件 `clear(row)` 对它编译期拒绝），门禁按这条判完备性。
    - **`.project(&Field::sub)` 与 `.token<...>` 两个旁注在本轮退役**。前者退役的理由是它与「逐键独立表态位」直接冲突：一个 `Font` 字段承载 `font_size` / `font_weight` / `font_family` 三个键时，表态位必须也按三键分，否则「只改字号」无法与「整体换字体」区分、单键撤表态（`clear(font_size_row())`）无处可撤。裁决是三键各自成行、各自一个可空字段（键集合与 schema 顺序不变，见验收判据第 1 条）。**聚合形态 `Font` 不再发合成读件 `font()`**：它不进表、不占属性键、不进 descriptor、不进序列化、也不计入覆盖率门禁的逐行计数，于是成为「模型无法从属性键枚举出来」的表外名字 —— 组装 `Font` 是绘制体自己的事，归控件私有的行为代码就地组（`on_layout` 里由 `font_size()` 拼一个局部 `Font`）。**同理组合便利写件也不发**：现状 `Button` 的 `set_border(c, w)` / `set_min_size(w, h)` / `set_disabled_colors(bg, text)` 三件同为表外名字，改为两行链式表态（`set_border_color(c).set_border_width(w)`），随本变更按破坏性撤除并记 CHANGELOG（见第 10 条与迁移块③）。`.token<...>` 退役的理由是它被 `.fallback(...)` 的**活令牌形态**完全包含，同一事实不该留两个拼写。
    - `.fallback(...)` 接受**三种实参形态、一个擦除槽**。① **活令牌档**：主题档成员指针，且必须以模板实参写作 `.fallback<&ColorRoles::primary>()` —— 把它放在普通函数形参位上时它是「指针的值」而非「指针的名字」，进不了 NTTP 槽（g++ 实测拒为「不是有效的模板实参」，改到模板实参位后 g++ / clang 双绿），模板实参位同时让「令牌成员类型 ≠ 该行裸值类型」在编译期即红。② **常量档的值形态**：`.fallback(14.0F)` / `.fallback(Color{0, 0, 0, 0})` / `.fallback(true)` —— 值 NTTP 对 literal 类型成立（浮点值 NTTP 是 P1907R1、字面量类类型 NTTP 是 P0732R2，均在 C++20 内），含 `std::string` 的类型不成立，所以这一形是**按类型可选的短写**、不是唯一写法（取证见附录探针 15，`Font` 一类的反例同表）。③ **库内默认提供者**：`&ButtonProps::padding_default`（`static auto () -> T`，常量档的通用形），以及**派生提供者** `&ButtonProps::hover_default`（`static auto (const Derived &, const BuildContext &) -> T`）—— 派生形是本轮新增的第三类回落点：`hover_color` / `pressed_color` 要回落到「当前作用域下背景色的调暗值」，前两形都表达不了。早期口径把回落点限定为「活令牌或常量」两形，实测漏了这一类（`Button` 15 行里占 2 行）；`border_color` 的回落点是**透明常量**，不属派生类，故它写值形态、按第 2 条的规则也就只有无参读件。三形共用一个擦除槽（槽内是「取生效值 / 取基线值的函数指针 + 令牌短名」），形态差异不落进字段形状、也不要求逐属性记忆 —— 它唯一决定的公共面后果是**该行发的是 `x()` 还是 `x(ctx)`**。
    - 行必须是 `static constexpr` **成员函数**而非数据成员（第 9 条其二，探针实测）；私有字段保持在类末尾，与既有排版纪律一致。
    - **子节点槽不进表**：`children` / `child` 一类节点槽留在 Props 作普通私有成员与 `set_children(...)` 一类具名写件，不占属性行、不进序列化属性段（走既有 children 通道）、无档位。逻辑回调（`on_click` 等）按裁决①留在控件本体公有成员，公共写法不变。
    - `rows()` 的顺序即 schema 里属性数组的顺序（现状为字段声明序），据此保持 639 条目的既有次序不变（见验收判据第 1 条）。

2. **读写面收口在 Props 类内：字段直写编译即红，`_source` 后缀写件并入同名过载、读件整体退役**。字段私有后，派生作用域（控件本体）**也访问不到基类私有成员**，于是 `props_.corner_radius_ = v` 一类的类内旁路连同外部 `btn.corner_radius = v` 一起被编译器封死，第 5 条缺陷的「内部半侧」不留残余、不需要 grep 门禁。写面全部经 `assign` / `rebind` / `clear` 三个通用件（各全库一份实现，非虚函数）：`assign(row, v)` = 读现值判等 → 写字段（不可空行写字段本身；来源行写「自有常量源」；可空行同时置表态位）→ 经宿主链接落该行档位；`rebind(row, src)` = 换绑句柄 + 落档 + 经库内链接位的 thunk 转调 `resubscribe_signals()`（实测它是 `Widget` 的 protected 成员、属性面取不到，故该通道由 `Widget` 在 `bind` 时自行装入，见第 7 条）；`clear(row)` = 撤表态、退回该行的回落点、落档（**只对非必填行实例化**；必填行传入即编译期拒绝）。读面是**四件库内通用件**：`resolve(row, ctx)` 给生效值、`stated(row)` 给表态值或未表态时的回落点基线值、`get(row)` 给不可空必填行的裸值（`stated` 的退化特例）、`read(row)` 给句柄。它们在公共面上各自**只在该行需要的那一个名字上出现**：常量回落行发 `x()`（`stated` / `get` 的具名件），作用域依赖回落行发 `x(ctx)`（`resolve` 的具名件），`read` **不升级为具名件**（实测零消费者）。第五件 `present(row)`（表态位）**只供库内**序列化与 Inspector 消费，不进任何公共签名。
    - **通用件升公共面的唯一判据：这一件没有逐属性替代**。`set_x` / `x()` / `x(ctx)` 都有具名件，故 `assign` / `rebind` / `resolve` / `stated` / `get` / `read` / `present` 全部留库内；只有撤表态不发具名件，于是 `clear(row)` 成为公共面上唯一的动作型通用件（表本体 `rows()` 是数据入口，另计），形参是 typed 的 `PropRow`，写法 `props.clear(ButtonProps::color_row())` —— 行本来就是 public `static constexpr` 函数，所以这个调用**完全可 grep、可跳转、零推导**，比逐属性 `reset_x()` 更透明；而形参取 typed 行而不是擦除槽，正是「必填行传入即编译期拒绝」得以成立的原因：`clear` 靠 `requires(!Row::is_required)` 读行类型上的位，擦除后的 `PropSlot` 只剩运行期数据，同样的判断只能退成「槽里存一个 `nullptr` 标志、跑到运行时才报」（未测项其四按此结案）。
    - **公共读面一条规则：每行恰一件，形态由该行回落点是否随作用域变唯一决定**。常量回落的行只有无参 `x()`，它同时就是生效值读件（回落点不随作用域变，「表态值 / 基线值」与「生效值」两个答案恒等）；回落点随作用域变的行 —— **活令牌档与派生档两类**（第 1 条末注的第三形）—— 只有 `x(ctx)`，**不发无参件**。上一轮口径「无参 `x()` 对全部行同形 + 活令牌行再发 `x(ctx)`」经 Button 全量重写探针否掉：它在同一行挂两个同名读件、给两个不同答案，选错**不报错、只是值不同**，恰是本提案要消灭的那类静默错形；改成一行一件后，`padding(ctx)` 与 `color()` 两个误写形态都**编译即红、当场自纠**，歧义面为零，且「少发名字」不再依赖门禁。面有多大：639 条属性 / 351 条非基类行里，schema 带 `default_expr = "theme.*"` 的 47 条加上派生档行（`Button` 样本 15 行中 2 行；全库派生档计数未测，接入 `ShapeScale` / `SpacingScale` 后按实数更新），`x(ctx)` 只发这么多，而不是按 351 行全发；无参件 `x()` 那一边则由「全行发」降为「非作用域依赖行发」。句柄读件 `x_source()`（现状 `label_source()` / `background_source()` 一类）随之整体退出公共面 —— 实测 218 条判据无一条需要它：序列化与信号收集走表、外部订阅走 widget 级信号，它是纯粹的表外名字。`resolve_` 前缀仍退役；现状 `Button::resolve_background()` 一类私有派生函数改为转调 `color(ctx)` 的调用点糖。**这条与上一轮修订是对撞而非补充**：上一轮的口径是**每行件数**（二～四件），本轮的口径是**同一行有没有两个答案** —— 后者更贴「模型第一次读对」这条判据，因为它治的不是数量而是静默选错；数量侧的收益见第 0 条的实测公共面清点。
    - **可空 ⇔ 非必填，`std::optional` 只活在私有存储层**。第 6 条把回落点变成每行必备之后，可空性不再是「这行有没有令牌」的函数，只剩下「这行是不是必填件」这一个分叉；而必填件（`Button` 的 `label`、`Text` 的 `content`）本就不该有回落——「未填的文本」回落成空串是假值而不是默认值。所以判据更简单、也仍机械可判：`required()` 行裸 `T` / 裸句柄不可空，且公共件 `clear(row)` 对它编译期拒绝；其余行一律可空、一律可被公共件 `clear(row)` 撤表态（不发逐属性 `reset_x()` 的理由见上方「通用件升公共面的唯一判据」那段）。无回落点的裸 `T` + 声明处默认值这一形态本轮**取消**（原样保留会留下「同一事实两处住处」：默认值在字段初始化器、回落点在行上）。
    - **来源 + 回落的复合形态写作 `std::optional<ReadOnlyState<T>>`，不写现状的 `ReadOnlyState<std::optional<T>>`**。后者有两重空态（句柄未绑 / 句柄内值为空），组合出「句柄存在但值为空」这种既非表态也非回落的状态，公共签名里还带 optional；前者只有一重（未表态），句柄一旦存在其 `get()` 就是生效值。这是**破坏性**类型变更，随第 10 条迁移。
    - 被否决的三种「不用 optional」写法，各自的失败模式是：**哨兵值**（`0` / `Color{}` / `-1` 表示未设置）—— `corner_radius = 0` 是合法的直角、`Color{}` 是合法的不透明黑，哨兵与真值不可区分，正是本条要消灭的那类假阳；**旁挂存在位**（裸 `T` + `bool set_` 或一张位图）—— 两份状态可各说各话，写值忘改位即骗人，且序列化 / 判等 / 发射三处都要各自记得读位；**`std::variant<token_ref, T>`** —— 它与「可空 + 回落点在行上」信息量相同，但把同一件事分在两处表达（变体里的令牌引用 vs 行上的 `.fallback`），冲突时无从裁决。判等短路（`set` 内）仍按现状推广为通用件里的统一规则。
    - 同样否决**引入属性封装类型 `Property`（薄封装，自带 getter / setter / reset / row）**：它替代不了任何一行公共代码（C++ 生成不了方法名，除非上第 10 条明确不做的构建期代码生成），只把 `std::optional` 改名成封装类型并把「公共面不得外泄可空性」这条门禁改成还得再拦一层；而它成立的前提（键名与回落点进类型、即 class-type NTTP 自述）本轮未实测。第 6 条的强制回落落地后，形态族已由五类降到两类（值型 / 来源型，各乘是否必填），封装类型能省的只剩「异构 optional 的模板噪声」一点收益，不足以抵上述代价。**采纳其中一条洞见**：正因为 `assign` / `resolve` 要跨两种可空形状做 `if constexpr` 分叉，探针 13 才撞上「const 成员函数里取字段类型必须 `std::remove_cvref_t`」这个真错形 —— 该纪律保留为落码要求。
    - **同名过载成立**：值型写件与换源写件共用一个名字（`set_color(Color)` / `set_color(ReadOnlyState<Color>)`），实参为值时精确匹配胜过用户定义转换，不产生二义（探针 10，Button 全量重写里同款过载再证一次）。现状的 `set_background_source` / `background` 两个异名入口并入 `set_color`；`_source` 后缀从公共 API 退役 —— 写件侧并入同名过载，读件侧（`label_source()` 一类）**整体不发**，理由见上方「公共读面一条规则」那条。
    - **字符串型属性必须保留便利重载**：`ReadOnlyState` 的转换构造刻意非 `explicit`，故以 `const char *` 或 `std::string` 实参调用时值型与句柄型两条用户定义转换序列同rank，编译器报无匹配（探针 11，三套编译器一致）。解法即现状 `button.h` 已采用的形态：`set_x(LocalizedString)` / `set_x(const std::string &)` / `set_x(const char *)` / `set_x(ReadOnlyState<LocalizedString>)` 四重载，前两个转调第一个。门禁按属性类型校验重载齐备（见第 7 条）。

fallback 形态决定"}`。它是**一次性常量块**（不随控件数增长，约 0.4 KB，与 `source` 位的约 +2 KB 同批计入额度），换来消费方不必读头也能推全名 —— 这是「让每属性手写一行以便 grep 看得见」那条退路的替代品，后者要让全库 639 个属性都付抄写成本。**基类属性 `width` / `height` / `show`** 的描述条目现状由 30 个控件头各手写一遍，本变更收口为库内一份基类槽表，发射时并入每控件的条目（次序不变）。控件若有**非属性**序列化物（容器 children、`TextInput` 选区），其覆盖体在转调基类后自行补键。**序列化口径由「令牌行未表态不写键」扩为「全部非必填属性未表态不写键」**：落盘的是意图，不是某一刻的生效值 —— 现状把裸 `T` 属性的声明处默认值也一并写盘，于是一次保存就把用户从未要求的默认值永久烘进配置文件。`Button` 的 `on_paint` 等既有行为代码里，作用域依赖回落的行改走 `x(ctx)`、其余行改走 `x()` —— 按第 2 条「每行恰一件」，两类行各只有一个名字可写，走错的那一侧编译不过，所以这条分工不再需要由门禁在人一侧守（第 9 条的相应判据随之改为声明面检查）。现状 `Button::resolve_background()` 一类私有派生函数保留为行为侧的调用点糖，函数体改为转调 `color(ctx)`。**schema 只给「推导不出来的那位」，不给名字清单**：曾评估把每个属性的公共访问器全名逐条写进 `aurora_api.json`（模型据此一次读全公共面，不必 grep 头文件），按实测口径否决 —— 现 schema 为 206,097 字节 ≈ 51.5k tokens，`check_api_budget` 的天花板是 75k，而按现格式逐条追加五个方法名估 +70 KB（≈ 69k tokens），吃掉剩余额度的八成；这些名字又全可由「词根 = 属性键名」+ `required` + `source` + 「该行回落点是否随作用域变（决定发 `x()` 还是 `x(ctx)`）」推出。实测再补一条口径事实：`aurora_api.json` 的 widget 条目结构是 `type` / `props` / `events` / `children_policy` / `examples`，**只登属性键、不登方法名**，所以公共访问器数量的增减本身不动 `check_api_budget`（2026-11-03 实测 206,103 字节 ≈ 51,526 / 75,000 tokens）—— 本轮公共面收窄的判据因此不是 token 额度，而是「全库符号面能否被枚举对」与「每个公共件按 `codespec/CODING_STANDARDS.md` §13 写全注释」两项成本，后者随逐属性宏一次解决（第 10 条）。所以本轮 schema 的扩面就是 `source` 一位（约 +2 KB），而 `default_expr` 已经承载「哪一行跟随主题」这一事实：第 2 条决定 `x(ctx)` 发不发、第 9 条决定门禁判不判，读的都是它，不新增第二个字段。

4. **反序列化写当前源、不断绑（一处真实缺陷的修复，附带一个状态层前置依赖）**。现状 `Button::deserialize_props` 对 `color` 键转手 `set_background_source(...)`，把控件**换绑成常量源** —— 用户绑定的 `State<Color>` 被一次 Inspector 热回写悄悄断绑。本变更规定：`props_deserialize` 逐键走 `assign`，**写当前源的现值**，换源只走 `set_xxx(ReadOnlyState<...>)`。但 `ReadOnlyState<T>` 按设计**只有 `get()` 与 `subscribe()`，没有任何写入路径**（其实测形态见 `include/aurora/state/read_only_state.h`：来源节点 `source_` 私有，仅友元 `detail::HandleAccess` 与 `StateSink`），故「写当前源」需要状态层新增一个**库内**通道（`detail::HandleAccess` 增一个写形参的静态成员，或把该通道友元授予 props 层）。这条列为实施前置项。曾评估并否决两个替代：其一，把字段类型改为 `State<T>` —— 那会让所有属性变成外部可写，直接违反句柄权限纪律；其二，保留「反序列化即换绑常量源」 —— 即把上面那个已被点名的静默断绑缺陷原样留下，不可接受。

5. **标脏经宿主链接落档，不新增标脏代数**。行的档位（`Layout` / `Paint`）编译期给定，`assign` / `rebind` 通过 `Widget` 既有的公开入口 `mark_needs_layout()` / `mark_needs_paint()` 落账 —— 本变更**不引入**新的 `mark_for(Dirty)` 入口与格合并代数：实测 `mark_needs_layout_impl` 现状无「已置位即返回」短路，批量写入的落账次数与今天逐处手写同量，性能口径不回退也不新宣称收益；若后续要做幂等短路，另案处理。**判等短路的类型条件**：`assign` 里的 `if (slot == v)` 必须包在 `if constexpr (std::equality_comparable<bare_t>)` 内 —— 实测 `EdgeInsets` 没有 `operator==`（`Color` / `LocalizedString` / `Font` 都有），无比较算子的类型退化为「无条件写入 + 落档」。这不是缺陷而是取舍：多标一次脏只是多算一帧，静默漏标才是缺陷一的成因。后果如实记 —— `padding` 一类属性「写入同值也标脏」，与其他属性行为不同，单测按类型分档断言（Button 全量重写探针已把它写成判据）。`mark_needs_*` 的**非属性写入**用法（hover / focus / 光标 / 滚动偏移 / 自驱动动画的 `on_paint` 末尾自调度）原样保留，迁移后剩余每一处必须属非属性写入，由门禁逐处点名。**事件粒度**：`collect_signals` 由表派生为控件侧一行，`on_signal_dirty()` 虚函数与「并集双标」粒度**本轮保持不动**（`Provider` 的唯一覆盖与整子树清零不受影响），逐源精确档位需 `StateSink` 新增按键回调的接口，属状态层扩面，按 §11.3 最小 API 原则不在本变更内做（列为后续候选，触发条件：出现「只绘制档来源属性变更却触发整树重排」的实测性能证据）。

6. **回落点强制：每个属性行要么给 `.fallback(...)`、要么标 `.required()`；`Theme` 增设形状 / 间距 / 动效三枚令牌组；活令牌是成员指针、延迟解析；显示串只在序列化边界**。前半个分句是本条的新增裁决，它把「有无回落」从**属性之间的差异**降为**同一机制的实参选择**：`.fallback<&ShapeScale::medium>()`（活令牌，随作用域换肤）、`.fallback(14.0F)`（常量值形态，literal 类型可用）、`.fallback(&ButtonProps::padding_default)`（库内默认提供者，常量档）、`.fallback(&ButtonProps::hover_default)`（派生档，回落点要读 ctx 与他行现值）—— 后两写同形、由签名区分。这样做的理由不是审美 —— 只要「有些行可空、有些行裸 `T`」这个分叉存在，存储面就必须按行分叉（裸 `T` 还是 `optional`）、写件与门禁也跟着按行分叉（`clear` 能不能实例化、判等要不要先看表态位），而 `assign` 就要在三种字段形状上做 `if constexpr`，这几处分叉说的其实是同一件事。**强制回落后，存储面与序列化面的分叉只剩「是否必填」一处**，而 `required` 已经是 schema 里导出的布尔位，两面的公共件与门禁都只按它分一次。读面另有**一处按「回落点是否随作用域变」的分叉**（第 2 条：这类行只发 `x(ctx)` 且不再发 `x()`，常量行只发 `x()`），它不落进字段形状、也不要求逐属性记忆 —— 由表判、由第 9 条的声明面门禁判；另一侧的名字根本不存在，所以误用在调用点就是编译红。`Theme` 增加 `ShapeScale`（圆角档）、`SpacingScale`（间距档）与 `MotionScale`（动效时长档）三枚令牌组（形态、为何不做成扩展位、以及新增一枚档的实测落点成本见第 11 条前置二），与既有 `ColorRoles` / `TypeScale` 同构（强类型字段、逐字段声明处默认值），「裸主题 = 明色基线」的 `with_defaults()` 口径不回退 —— 它现在服务的是描述符与往返复原口径（未表态行经回落点求值出与旧输出一致的生效值），不再是「公共无参读件的诚实性前提」，因为活令牌行已经没有那个件。`.fallback` 的活令牌形态在编译期烧成一次成员指针解引用，满足 `codespec/specification/07-environment-modifier.md` §5「stringly 只允许存在于序列化边界，不进渲染路径」的既有裁决，**令牌改名即编译失败**（成员指针失配），而现状 50 处 `"theme.` 显示串改名的只有静默回落；`default_expr` 由发射侧据行上的回落点自动派生（每个 Scale 类型在自身头文件就近登记一张「成员指针 → 短名」编译期对照表，每类型一次约十行，门禁校验表 ↔ 实际字段一致），落盘走 `src/aurora/widget/serialization.cpp` 既有分支，schema 结构不变。可空行的字段可空（第 2 条：值型 `std::optional<T>`、来源型 `std::optional<ReadOnlyState<T>>`）：**布局 / 绘制取值时**经 `inherit_theme(ctx)` 解析，**绝不在构造时烘进值**；未表态不序列化；**生效值读件是带 ctx 的 `x(ctx)`，且只对回落点随作用域变的行存在**；常量行的 `x()` 就是生效值读件（两个答案恒等，第 2 条）。于是**渲染路径里不存在「选错读件」这件事**：作用域依赖行没有无参件可写，写 `color()` 当场编译红 —— 本条早先设想的「按函数作用域切段拦无参读件」的门禁因此不再需要（未测项其三据此结案，第 9 条改为声明面检查）。同构先例仍是 Flutter `ButtonStyle`：它的每个样式字段都可空、统一经 `resolveWith(style, defaultStyleOf(context))` 合并 —— 本轮把 Aurora 收拢到同一形态；Flutter 缺的是「显式表态成同值」与「未表态」的区分（Dart 的 `copyWith` 无法区分显式 `null` 与未传参，这是其已知缺陷），正好由本条的表态位补上。
    - **活令牌形态的成员类型 = 该行裸值类型**（`.fallback<&ShapeScale::medium>()` 与字段类型不匹配时，行上的 `static_assert` 与成员指针解引用都会编译即红，这是强类型形态的固有约束，不是新增规则）。因此间距档 `SpacingScale` 的直接消费端是 `Column` / `Row` 的 `gap`、`Grid` 的 `gap`、`Form::set_gap`、`ReorderableList` 的 `gap` 一类 **float** 属性（实测库内 6 处同型字段）；`EdgeInsets` 型属性（如 `padding`）**不接活令牌** —— 四边结构与单一标量档不同型，要接必须先决定「一个档展开成四边同值」还是「一组四元档」，那是新的语义而非本变更的遗漏，按 `CODING_STANDARDS.md` §11.3 最小 API 原则另案。注意这与强制回落不冲突：`padding` 用库内默认提供者形态给回落点，字段照样可空、照样能被公共件 `clear(row)` 撤表态、照样在未表态时不写键；代价与收益是同一件事：它**只有 `x()` 这一个读件**（第 2 条），而在常量回落的形态下该件取到的就是生效值。于是「接不接得了活令牌」不再只是观感问题而是有公共面后果的判定，后续给 `EdgeInsets` / 字号族接档时（另案）必须连同「该行是否随之获得 `x(ctx)`」一起裁。字号 / 字重 / 字体族三个键同属此列 —— 它们各自成行（第 1 条末注），回落点本轮取库内默认提供者，接 `TypeScale` 的活令牌档要等「档成员类型与裸值类型同型」这条约束被满足（`TypeScale::body_medium` 是 `Font`，不是 `float`）。

7. **宿主绑定与移动：一处纠正 —— 不用相对偏移重绑**。Props 需要一个 `Widget *owner_` 才能落脏。`Widget &` 不可行（聚合式构造无初值、且 `Widget` 是移动型对象）；早期结论「`AbstractProps` 的移动构造按构造期记录的**相对偏移**自动重绑」经探针复核**被否**：偏移法在「把已绑定的 Props 从活控件里切出来搬移」时会在宿主之外算出一个地址并当作 owner 使用，即伪造指针 —— 那比它要修的缺陷更糟。本提案改为两点、同样零控件手写：① `Widget` 增加一个指向其属性对象的**库内链接位**（`PropsLink *`，非模板、非虚），`bind(host)` 在控件构造尾部写下它并记 owner。**重订阅通道的落码形态由探针纠正**：换源重订阅要走的 `resubscribe_signals()` 是 `Widget` 的 **protected** 成员，基类属性面取不到它，于是探针让 `bind` 多收一个宿主给的 `std::function<void()>` 回调（写法 `bind(*this, [this] { resubscribe_signals(); })`，行为侧 218 条判据全绿）—— 该形态**只作行为取证、不作落码形态**，因为 `std::function` 成员每次控件构造挂一次堆分配，与验收判据第 10 条的「零堆分配」直接冲突。落码改为：`PropsLink` 里由 `Widget` 一侧装入一个指向自身 protected 件的**库内 thunk**（`Widget` 在自己的类内当然调得到它），属性面只经 `link_->resubscribe(*host_)` 触发 —— 公共面不加名字、protected 面不放大、零分配。行为契约以探针已证那份为准：换源即重订阅、未挂载即不标脏；② `Widget(Widget &&)` 与 `operator=(Widget &&)` 从 `= default` 改为库内一处定义，把链接位的 host 指向新对象，属性子对象自身的移动构造再把链接位指回自己 —— 于是「整控件移动 / 移动赋值」自动保脏（探针 12：连续两次移动与移动赋值后 setter 仍命中新宿主）。配套规则：**拷贝不携带绑定**（属性对象的拷贝构造刻意丢 owner，拷贝即新 DTO），**控件构造尾部必调 `bind(*this)`**（模式门禁逐控件校验；重订阅不需要宿主另给回调，见上一条的落码形态），「把已绑定的 Props 切出宿主搬移」不在支持面内（无悬垂、无伪造指针，最坏退化为不标脏，且公共写法到不了这条路）。附带收益：脱离宿主的 DTO 上 `owner_ == nullptr`，链式构造因此天然不产生任何标脏 —— 构造装入不需要 init 通道，也不需要早期形态里的「Dirty 返回值 + 落账仪式」。

8. **构造面：链式即形态二的新定义**。`XxxProps` 类化后不再是聚合，`Button(ButtonProps{.label = "OK"})` 这条 §11.1 现文推荐的写法编译失败（探针 9 的同族事实：字段私有 + 基类存在，两条路都不通），替代为链式：

    ```cpp
    auto btn = au::Button(au::ButtonProps().set_label("OK").set_corner_radius(8.0F).set_enabled(false));
    btn.set_on_click(fn);                                   // 回调仍按现状（形态一，逐名、顺序无关）
    auto col = au::Column(au::ColumnProps().set_children({au::Text("A"), au::Text("B")}).set_gap(8.0F));
    ```

    逐属性显式名、顺序无关、漏写者回退该行的回落点（第 6 条）—— §11.1 形态二的精神（AI 只需记「属性名 + `*Props`」、可分块生成）完整保住，且写件名与第 2 条的写面同名同物，不新增第二套词汇。位置式**首参便利重载**保留（`Button("OK")`、`Slider(State<double>, on_changed)` 一类跨类型、无跳位需求者，现状已在用）。`defaults()` 仍在（返回默认构造的属性对象，即**全部非必填件均未表态**），但字段私有后只能经 getter 读，且无参 getter 读到的是回落点基线值（tests 内 4 个控件单测的 `const ButtonProps d = Button::defaults();` 形态随之改写）。**破坏性口径**：`codespec/CODING_STANDARDS.md` §11.1 与 §2 的「具名聚合优先」条目、`codespec/specification/04-widget.md` §2.5、`codespec/specification/09-cli.md`、`codespec/specification/08-tooling.md` §10.3 的 `DesignatedInit` 发射风格一并改述；codegen / LSP 的 golden 与 `examples` 字面串（`describe_static` 里的 `.examples = {...}`）同步重写；迁移以编译器指认为准（`XxxProps{` 实测 481 处构造点 / 146 文件，其中指定初始化器风格 379 处；`codespec/` 文档内 82 处写法随文档改）。迁移期可用一次性脚本辅助批量改写，脚本不进 `tools/`、不入库。

9. **schema 与门禁：扩面只两处（一位布尔 + 一个顶层规则块），一致性全部机械判定**。档位 / 响应 / 投影是库内实现事实，无库外消费端，不进 `aurora_api.json`；本轮 schema 扩面 = 条目内布尔位 `source` + 顶层 `accessor_rules` 规则块（第 3 条末：前者是公共名可推导所必需的最小位，约 +2 KB；后者是一次性常量块，约 +0.4 KB，把宏形态下唯一失去源码实体的推导规则登记进机器可读面，现量 206,097 字节 ≈ 51.5k tokens 对 `check_api_budget` 的 75k 天花板仍在额度内）。门禁增改：
    - `check_props_table_coverage`（新增，纯文本判定）：三方计数 —— 私有字段数 ↔ `*_row()` 行数 ↔ `rows()` 里被点名的行数；`x_row()` ↔ `set_x(...)` ↔ 读件按命名对应校验，且每行必须命中 `.fallback(...)` 与 `.required()` **二选一**（都不写即红）。**读面词根规则由两条并为一条**（第 2 条的镜像）：每行**恰有**一个读件 —— 回落点是常量形态（值形态或库内默认提供者）的行必须有 `x()` 且**不得**有 `x(const BuildContext &)`；回落点随作用域变的行（活令牌档 `.fallback<&Scale::member>()` 与派生档 `static auto (const Derived &, const BuildContext &) -> T`）必须有 `x(ctx)` 且**不得**有 `x()`。两个方向的漏写与多写各判一次红：前者守「不发那三百个名字」，后者守「同一行不留两个答案」。**来源性不再作为旁注判定** —— 门禁改读字段形状（`ReadOnlyState<T>` / `std::optional<ReadOnlyState<T>>`），表上出现 `.source()` 即红（重复声明推导得出的事实，第 1 条末注）。撤表态**不得有具名件**：全库出现任何 `reset_<属性名>()` 声明即红，退回回落点只有公共件 `clear(row)` 一条通道（必填行传入它编译期拒绝，因此不需要门禁参与）。**表外名字一律不得出现在 Props 的公共面**：`*_source()` 读件、合成读件（`font()` 一类）、组合便利写件（`set_border(c, w)` / `set_min_size(w, h)` / `set_disabled_colors(bg, text)` 一类）任一声明即红 —— 它们不进表、不进 descriptor、不进序列化，是模型从属性键推不出来的名字；第 0 条那句「公共面除规则件外只剩 `clear` 与 `rows`」由这条机械守住。
    - `check_no_contextless_property_read_in_render_path` **本轮撤销**（「未测项其三」随之结案）。撤销的理由不是难判而是**不必判**：按第 2 条「每行恰一件」，作用域依赖回落的行根本没有无参读件可写，在渲染路径里写 `color()` 就是编译红；常量回落行根本没有 `x(ctx)`，也没有可错的对象。于是这条防线由「函数体按作用域切段判定」上移到「声明面判定」（即上一条门禁里那两个方向的漏写 / 多写检查），误报面为零、也不需要解析函数作用域。早先写的退路（切段判据误报不可控即降级为 `codespec/CODING_STANDARDS.md` §6 书面纪律 + 评审清单）随之作废 —— 声明面判定不存在不可控情形。若日后某行既发无参件又发带 ctx 件（即回退到上一轮「同名两件」形态），必须先撤销这条判据再另案提案，不许悄悄把第二个名字补回去。
    - `check_no_optional_in_public_signature`（新增）：`include/aurora/**` 公共面的属性写件参数与读件返回值里不得出现 `std::optional`，**也不得出现任何属性封装类型**（豁免仅限本就承载「可空」语义的非属性接口，逐处登记）。这条把第 2 条的「optional 只活在存储层」变成机械判据，顺带拦住的正是 `ReadOnlyState<std::optional<T>>` 这一类双重空态。
    - **公共面通用件白名单**（并入 `check_naming_conventions` 的判定段，不新起脚本）：`include/aurora/**` 的 public 区里，来自 `AbstractProps` 的名字**只允许 `clear` 与 `rows` 两个**（`clear` 是唯一无逐属性替代的动作件，`rows` 是表本体的数据入口，二者各全库一份）；`assign` / `rebind` / `resolve` / `stated` / `get` / `read` / `present` / `bind` / `props_descriptor` 任一出现在公共面即红。这一条守的是第 2 条「只有无逐属性替代的通用件才升公共面」那条判据 —— 它一旦失守，读面就会从「具名件 + 可推导」退化成「通用件 + 行选择器」，而那正是被否决过的形态（每属性查声明才知道怎么读）。
    - `check_widget_bind_pattern`（新增）：每个公有继承 Props 的控件，其构造尾部必须出现一次 `bind(*this)`；缺失即红（这是对第 7 条唯一手写仪式的守护）。
    - `check_no_direct_field_write` 不再需要：字段私有，绕过写件的代码编译即红。
    - 手写 `mark_needs_*` 剩余清单逐处登记成因，未登记的新调用点即红；`"theme.` 字面量在 widget 源码中归零（仅令牌对照表与 schema 发射层允许）。
    - 令牌对照表 ↔ Scale 字段一致、枚举登记表 ↔ 枚举量一致；渲染路径（layout / paint 取值链）grep 无令牌名字面量。
    - `check_doc_comments` 覆盖新增公共头与行工厂；**访问器改由逐属性宏发射后，本门禁的判定单位从「每个公共成员函数」改为「每个宏调用点 + 宏定义处一份文档注释」**（第 10 条）。`check_naming_conventions`、`check_code_doc_sync`、`check_codespec_xref`、`check_change_proposals`、`check_umbrella_header`（新头入伞头与 manifest 基线）等既有门禁不回退；文本型门禁对宏展开的可见性是采纳宏的**前置取证项**，见「未测项」新增条目。

10. **范围边界（明确不做，以及本轮唯一采纳的宏）**：不引入构建期代码生成（Qt moc / Unreal UHT 形态）、**主题侧六处不做**（① 默认打开的 seed→HCT 动态取色 / 色调板派生 —— 裁决理由**只剩可预测性一条**：派生链把「主题 = 可枚举值对象」变成「主题 = 输入的函数」，模型经 schema 读到的是推导结果而非可核对的字面常量，与本库「AI 直接给角色」的取用方式正面相反。**成本不是论据**（material-color-utilities 有官方 C++ 实现，先文「需千行感知色科学代码」的说法经取证作废，不得再用它替这条辩护）。改后的允许形态：只作**离线 / 构建期**的可选 helper —— 由 seed 展开成明暗两列字面常量再落码，运行期不做派生、不作为默认书写路径；② 运行时加载外部主题包 / 自建 CSS 或令牌解释器 —— 撞 `codespec/SPECIFICATIONS.md` §4.2「不做又一套 CSS、不引入样式表语言」的既有非目标与静态库零开销交付；③ `ThemeData.lerp` 一类的换肤插值 —— 属动画子系统，另案；④ 运行期换「风格 / 换代」而非换值 —— Qt 已实证其代价（`QQuickStyle` 不允许注册后切换，切换即重建控件树），本库主题只换值不换代；⑤ DTCG / Figma 变量的双向往返 —— 只做单向导出，导入闭环属设计侧，导出工具另案；⑥ 把 `ThemeExtensions` 扩展位当作属性回落来源 —— 理由见第 11 条前置二，不是成本问题而是形态不可求值）、**不引入属性封装类型**（`Property` 一类的薄封装自带 getter / setter / reset / row；理由见第 2 条末注 —— 它省不掉公共代码，只把可空性换个名字），不引入运行时反射库、不引入 `mark_for` 与合并代数、不改渲染管线与布局算法、不改 `State` / `ReadOnlyState` 的公共值语义与判等（第 4 条那个库内写通道除外，且它不改公共面）、不给 `Theme` 加明暗以外的第三色列、不动 `third_party/`、不改 `PropDescriptor` 结构、不改 schema 层级与属性键集合及顺序（**条目字段集只新增一位 `source`**，理由与实测字节口径见第 3 条末；除此之外字段集不变，口径变化只发生在既有条目的取值：`default_value` 改由回落点派生、未表态属性的键从落盘输出里消失）、不删 `on_signal_dirty()`、不给 `EdgeInsets` 一类不同型属性接活令牌（回落点走库内默认提供者或值形态）。一次性示例确实无法配套单测的按 `AGENTS.md` 硬规则 7 就地标注。C++26 静态反射成熟后，行上的键名字符串半区可由反射补出，其余一切不变。
    **逐属性宏 `AURORA_PROP(<词根>)` 本轮采纳**（这是口径变化：上一轮把它记作「暂缓」，判据是你定的那一条 —— 只有最需要、宏收益最大的地方才用宏；而探针清点出的那 30 个一行转发件正是全库最大的一处样板）。范围严格限定为**只发访问器**：由词根发 `set_<词根>`（含来源行的句柄重载、字符串行的两枚便利重载，探针 11 证明它们必须存在）与 `x()` / `x(ctx)` 中由 `decltype(<词根>_row())` 推出的那一件，件件转调既有通用件。**不发权威表** —— 表要带 `.fallback(Color{0, 0, 0, 0})` 一类的含逗号实参，塞进宏会碎，而且表本身是给人读的自然语言；**不发 `AURORA_WIDGET` / `AURORA_PROPS`** —— 那两条早先已判不发，控件侧只剩四行转调、本就没有样板可省。收益：`ButtonProps` 的类体从「15 行表 + 30 行手写转发」缩成「15 行表 + 15 行宏」，公共面名字数不变、手写源码与 `@brief` 注释成本减半、访问器与表同源不可能漂移（第 9 条的读面词根规则从此在宏定义处一次成立）。代价与前置拆成**两条判据**（见「未测项」新增条目，两条都过才留宏）：**其一 机器侧可见性** —— 文本型门禁（`check_doc_comments` / `check_naming_conventions` / `check_props_table_coverage`）与 `tools/gen` 的 API 生成器对宏展开的可见性，判据是同一个人造违例（漏点名一行 / 漏一件读件 / 漏一段注释）在宏形态与手写形态下转红一致；**其二 模型侧第一次读对率** —— 本仓库已有 `itest_to_code` 与 `itest_mcp` 两条「自然语言 → UI 代码 / MCP 实时编辑」通道，它们本身就是「模型读这套 API 能否一次写对」的自动化测量，宏落地前后对同一组需求各跑一遍，生成失败率或 golden 一旦漂移即不合格。两条任一测不平，退回 30 件手写转发并把本条改回「不引入宏」；该退路不改变公共面名字与 schema 内容（`accessor_rules` 块仍保留，因为它记的是规则而非发射方式），只改手写量。附带一条读侧事实：宏不改变「可 grep 到词根」——调用点 `AURORA_PROP(corner_radius)` 与行函数 `corner_radius_row()` 都含词根，失去的只是签名行这一处实体，而它的信息量已由 `source` 位 + 规则块覆盖。

11. **主题侧并轨 · 三项前置（不做则本变更自身留缺陷）**。属性表化把「未表态 ⇒ 查作用域」从实测 51 处手写 `value_or(inherit_theme(ctx).roles.X)`（跨 24 个文件）变成**每个未表态行每次取值都走一遍**的通用机制，于是主题侧三件事从「可优化」升格为「前置」。

    - **前置一 · `inherit_theme` 改返回 `const Theme &`**。本机实测 `sizeof(Theme)` = **816 字节**（`ColorRoles` 152 ＋ `TypeScale` 600 ＋ `CsdRoles` 32 ＋ `ThemeExtensions` 24 ＋ 档位标记与对齐；MinGW g++ 16.1 单编译器读数，另两腿见「未测项」其六），而 `include/aurora/theming/theme_scope.h` 的现签名**按值返回**，`TypeScale` 的 15 枚 `Font` 各含一枚 `std::string family` —— 故每次调用是 816 字节整值拷贝**加至少 15 次字符串分配**。读取热点：`include/aurora/widget/pickers.h` 一个头 8 处、`include/aurora/widget/chip.h` 与 `include/aurora/widget/bottom_nav_bar.h` 各 5 处，`src/aurora/widget/widget.cpp` 与 `include/aurora/widget/menu_bar.h` 还各有一处把整份 `Theme` 拷进局部量的写法。注入侧同样在拷：`include/aurora/widget/provider.h` 的 `rebuild_env(ctx)` 于 `on_layout` / `on_paint` / `on_mount` 三处每次都把值塞进 `include/aurora/environment/environment.h` 的映射，而 `with<T>()` 连父映射整份堆拷贝。**本变更把解析点从 51 处扩到「全部未表态行的全部取值」，引用化不做等于用一个重构把现状缺陷按属性数放大**；且 `codespec/GUIDELINE.md` 现文「`Theme` 角色为直接字段访问，无哈希查找、无堆分配」这句既有承诺在按值返回的现实下不成立（无哈希成立、无堆分配不成立）—— 本条不是新增的性能优化，而是把那句已写下的承诺从假变真。形态：快照有稳定宿主（同批一的唯一物化点），`inherit_theme(ctx)` 返回其引用；无注入路径经一个函数内 `static const Theme` 兜底（UI 单线程，C++11 magic static 足够），顺带把「两兜底不同口径」这条既存偏差并掉 —— 现状 `inherit_theme` 兜 `Theme::light()` 而 `include/aurora/theming/theme_query.h` 的 `resolve_theme` 兜 `Theme::with_defaults()`，两枚兜底的 `scheme` 位不同。映射结构本身不动（`with<T>()` 的整份拷贝列为未测项其八）。
    - **前置二 · 三枚新档进 `Theme` 一等字段；扩展位明文不作回落源**。第 6 条已规定活令牌回落点是**成员指针**（`.fallback<&ShapeScale::medium>()`，令牌改名即编译失败），而 `include/aurora/theming/theme_extension.h` 的 `ThemeExtensions` 是 `void *` ＋ 线性 `typeid` 扫描、未注册返回 `nullptr`、**不可枚举、不可序列化、拷贝时逐条 `new`** —— 挂在那里的令牌组既拿不到短写法，也过不了「改名即编译红」这条判据。裁决：`ShapeScale`（圆角）/ `SpacingScale`（间距）/ `MotionScale`（动效时长）三枚做成 `Theme` 直接字段，与 `ColorRoles` / `TypeScale` 同构（强类型、逐字段声明处默认值、明暗无关故只一列），并在各自头文件就近登记「成员指针 → 短名」编译期对照表（第 6 条已定形态）。`ThemeExtensions` 保留给应用级自定义令牌并**明文写入规格：不参与属性回落**；`include/aurora/widget/chart_common.h` 的 `ChartPalette`（全库唯一库内扩展）因此继续走它自己的三级优先（显式 ＞ 扩展 ＞ 内置兜底）—— 那正是第 6 条「派生档 ＋ 库内默认提供者」的现成范本，其 `light()` / `dark()` / `fallback()` 三枚工厂返回值目前逐字段相同（明暗不分色），接线时一并裁。新增一枚档的实测成本如实记：触达 6 - 9 个文件，其中 `tools/check/umbrella_manifest.txt`、`codespec/ARCHITECTURE.md` 模块表、`codespec/specification/07-environment-modifier.md`、`aurora_api.json` 刷新**四处是纯人工同步点、今天没有任何门禁保证一致**；前置三把其中两处改为机械判定，其余由第 9 条的登记表门禁覆盖。
    - **前置三 · 令牌集合进机器可读面：顶层第二枚非条目块 `theme_tokens`**。取证四条：`aurora_api.json` 现收 77 条 `default_expr`，其中 47 条形如 `theme.*`、去重只剩 14 个 token；同一 token 在源码里有**三种拼法**（裸串、转义串 `"theme.primary"`、raw-string 形），分布跨 23 个文件，而 `tests/unit/utest_pickers.cpp` 已经把转义拼法**当契约断言** —— 不一致被测试固化了；`default` 与 `default_expr` 互斥（同时含两者者实测 0 条），所以 41 处主题回落被原生默认值吞掉、在 schema 里根本不出现；`ColorScheme` 未收录进 46 条枚举；`Provider<Theme>` 在 `src/aurora/widget/serialization.cpp` 以 `reg_no_props` 注册，故 schema 的 `ThemeProvider` 条目只有四枚布局属性 —— **主题载荷对消费方（模型、Inspector、CLI、MCP）完全不可见**。形态：与 `accessor_rules` 同批、同性质的**一次性常量块**（不随控件数增长），每条目记 `{短名, 所属结构体, C++ 成员路径, 是否明暗相关, 配对前景, 是否已被消费}`；`default_expr` 改为据表行回落点 ＋ 该表**生成**，源码内 `"theme.` 字面量归零；`ThemeProvider` 补主题载荷的表达。这是「以模型第一次读对为第一判据」在主题侧的兑现：现状 schema 写 `theme.primary`、C++ 真路径是 `roles.primary`，**没有任何文档规定这个前缀映射**，模型只能猜。额度如实记：两块合计约 ＋2.4 KB，基线 206,097 字节 ≈ 51.5k token，`tools/check/check_api_budget.py` 上限 75k —— 仍是一次性常量块而非逐控件扩面。

12. **主题侧并轨 · 四项同批（与属性层同构，且四项互相咬合）**。

    - **同批一 · `Theme` 拆成「稀疏覆盖面 ＋ 物化快照」两类对象**。现状 `Theme.roles` / `Theme.csd` 是**实体化的明暗两列**（`ColorRoles::light()` / `dark()` 逐字段手打常量，两枚工厂内共 92 处色字面量），于是「只改一个角色」必须整列抄一遍、`Theme::dark()` 一换就把用户覆写整体丢掉 —— 这正是属性层本轮用「回落点 ＋ 表态位」刚消灭的那类**现值与意图混淆**在主题层的同型复发，留着它，属性侧的裁决等于被自己的基座推翻。加重情节：`Theme` / `ColorRoles` / `TypeScale` **没有 `operator==`**（全库仅 `CsdRoles` 声明了 defaulted 比较），所以「主题到底变了没」在类型层判不了 —— 第 7 条的同值守卫在主题侧今天**写不出来**，`codespec/CONCEPTS.md` 只能示范「取现值 → 拷贝 → 改字段 → 整体写回」。形态：`ThemeOverride`（可写、逐字段可空，与属性层的表态位同构）＋ `Theme`（只读物化快照，逐字段裸值，由前置一/二那个唯一物化点一次性求出），嵌套沿树**逐字段合并**；业界在这一条上没有分歧形态 —— Fluent `ThemeProvider` 的 partial merge、MUI `createTheme` 的深合并、antd 嵌套 `ConfigProvider` 继承已改值、Flutter `Theme.copyWith` ＋ `InheritedTheme`，四家都是「只写覆盖项」。补 `operator==`，使「同值覆写不触发重排重绘」成为可断言项。**序列化口径与属性侧同条**：落盘覆盖面（意图）、快照不参与（生效值）—— 这是「落盘意图不落盘生效值」的第二处应用，不是新规则。顺带处置一条已坐实的文档/代码漂移：`include/aurora/theming/theme.h` 的 `@note Rebuildable: yes, via to_json / from_json（角色集；扩展不参与）` 与 `codespec/specification/07-environment-modifier.md` §5.1「主题 JSON 重建面：角色集经 `to_json` / `from_json` 进出」双双声称存在，而 theming 目录与 `src/`、`tools/` **零实现** —— 本轮**实现覆盖面侧**的编解码（覆盖面可逆、快照不可逆，恰好就是「意图≠现值」的机器可读形式），不是删注释了事。
    - **同批二 · 对比度从测试局部升为公共 API ＋ 静态门禁（并部分推翻一条既有裁决）**。取证：WCAG 相对亮度与对比度算法今天只活在 `tests/unit/utest_theme_roles.cpp` 的**测试局部 lambda** 里；公共面 `include/aurora/core/color.h` 只有 `shaded()` 与 `with_alpha()` 两处颜色运算，`include/aurora/core/color_space.h` 只有 sRGB↔P3 的 3×3 矩阵（无感知色空间、无色调板、无对比度）；测试断言只覆盖 **10 对** `on_*`，`outline` / `outline_variant` / `scrim` / `shadow` / `surface_tint` / `on_surface_variant`×`surface` 全不在内；`tools/check/` 现有 26 个脚本**没有任何主题 / 令牌 / 色字面量 / 对比度门禁**；而库自带两列的取值注释自称「按 M3 标准色调板从主色 seed 生成」，代码里 seed 与其余角色之间**不存在函数关系**（字面量是抄来的常量），所以两列一旦漂移无算法可保一致。业界的现状要分两半如实记：**判据与调整手段齐备，但门禁一家都没有** —— WCAG 2.2 SC 1.4.3（正文 4.5:1、大字 3:1）与 SC 1.4.11（非文本 3:1）是判定标准，M3 `ContrastLevel` 在派生期整族调 tone、MUI `ensureContrast`、Qt 6.10 `contrastPreference`、Apple 系统色的 light / dark / increased-contrast 三套值是调整手段，而本轮调研覆盖的框架里**没有一家在构建期或 CI 期对配色失败报错或自动纠正**（跑在运行期、派生期，或干脆交给设计师）。所以本条是**差异化裁决，不是业界惯例的补齐**；既有那句「不提供无障碍 lint」也不是落后，而是主动的范围收窄。推翻它的理由只有一条：本库把主题当**机器可读契约**交给模型生成界面，配色错误的代价被模型批量放大，而库自带的明暗两列是 92 枚**抄来的常量**、seed 与其角色间不存在函数关系 —— 这种一致性除算法外没有别的守护方式。这条理由必须原样进规格，不能写成「业界都这么做」。形态四件：① 公共 constexpr `relative_luminance(Color)` / `contrast_ratio(Color, Color)`（把那两枚测试局部函数提到 `include/aurora/core/color.h`，纯函数、零运行时开销）；② 新增对比度门禁（计划/待建 `tools/check/` 脚本）对库自带两列的**全部**配对断言；③ 用户覆盖面在物化点校验，运行期只出 `AURORA_LOG_*` 告警不硬失败，且**「门禁只管库内两列、用户自定义色不进 CI」这句必须写进规格**，否则会被误读成「自定义主题过不了 CI」；④ 门禁必须消费①而不是自带一份实现 —— 否则测试、门禁、库各说各话，正是现状的病。**冲突显式处置**：`codespec/CODING_STANDARDS.md` 现文「不提供对比度 / 标签缺失 / 焦点可达性等无障碍 lint（用户明确移出范围）」被本条**部分推翻** —— 仅对比度转为门禁项，标签缺失与焦点可达性维持移出范围；回写时保留该条旧编号、新增裁决条目并记版本日志，不静默改写（口径冲突必须留痕）。
    - **同批三 · OS 无障碍开关折进主题决策，消灭第二条通道**。取证：`include/aurora/core/accessibility.h` 的 `AccessibilitySettings` 是与 `Theme` **并行的第二条通道**（进程单例 `current_accessibility_settings()` 与 Environment 优先的 `resolved_accessibility_settings(ctx)` 两套入口）；`font_scale` 的实际消费点是 `src/aurora/widget/text.cpp` 两处**末端乘法** `f.size_pt *= ...`，即绕过 `TypeScale` —— 读 `type_scale.body_medium` 的四枚图表控件因此不受缩放影响，同一 App 内字号覆盖不一致；`high_contrast` **零生产消费者**（其注释「色 Responder 由各控件按此位取用」是未实现口径）；`include/aurora/environment/media_query.h` 的 `text_scale_factor` 同样零消费者（`tests/unit/utest_media_query.cpp` 只断言它恒为 1.0）；`reduce_motion` 有实质消费者但直读进程单例。形态：三项**继续住在与主题正交的环境轴上 —— 不新增 `Theme` 字段、不进 `theme_tokens` 表**（业界在这点上同样一致：Flutter 的 text scaler 走 `MediaQuery` 而非 `ThemeData`，Compose 的字号缩放住在 `Density` / 平台配置侧，Apple 的 `accessibilityReduceMotion` 是 Environment 值，Qt 把无障碍提示归 `QStyleHints`），只在**唯一物化点**作为**输入**折进快照 —— 物化点是两条轴的唯一交点，除它之外的读取路径一律不看这些开关，第二条通道因此消失而正交性保留。字号缩放作用于 `TypeScale` 解析并**带动非文本度量**（`SpacingScale` / `ShapeScale` 随 scale 增长；Apple `@ScaledMetric` 与 Compose `sp` 给出的同一条教训是「不带动度量就是溢出硬失败」，这是可达性不是观感），`high_contrast` 走「整族调 tone 的派生」而不是第三列手打常量（M3 `ContrastLevel` / Apple increased contrast / CSS `forced-colors` 的共同形态），`reduce_motion` 作为 `MotionScale` 的短路门（取零档）。读取入口统一为 `resolved_accessibility_settings(ctx)`，进程单例仅兜底。**平台侧不假装**：`os_color_scheme()` 通路已接通（`src/aurora/app/window_host.cpp`、`src/aurora/window/win32_host.cpp`、`src/aurora/window/macos_surface.cpp`、`src/aurora/app/application.cpp`，Linux 不假装实时），而高对比与字号缩放的 OS 推送在 Win32 / Linux 尚无统一读点 → 列为未测项其九；本轮只承诺「开关进决策」的机制与自测注入，不承诺全平台自动跟随。
    - **同批四 · on-color 配对自动回落，给「每行必须给回落点」减压**。业界形态是 Compose 的 `contentColorFor`：给定背景角色，前景自动取配对称、无配对称时按对比度在黑/白里二选一。落点：`theme_tokens` 表里给每枚前景角色标其配对背景角色（与前置三共用同一张表，不另造第二轮映射规则），于是 `on_primary` 一类的行在未表态时可由**配对称**回落，而不必把 38 枚角色名逐枚写进控件；配对缺失时退回同批二的 `contrast_ratio` 判定。意义：强制回落（第 6 条）之后，回落点的书写成本第一次有了机械替代品 —— 这是第 6 条与主题层的咬合点，不是独立特性。

13. **主题侧债务清偿：三笔「声明了却没人用」的账，本轮要么接线要么明文标注**。这笔不是新功能，而是前置三的直接后果 —— **`theme_tokens` 一旦把令牌全量导出，「可枚举但不可用」比缺档更坏**：模型会认为每枚角色都有消费者，据而写出实际不生效的界面（AI-first 项目里假面的代价高于空洞）。

    - **零消费死档**。`ColorRoles` 38 枚里实测无生产读取点的有：`tertiary` 族四枚、`inverse` 族三枚、`surface_container_low` / `surface_container` / `surface_container_high` / `surface_container_highest`、`outline`、`hover`、`pressed`、`shadow`、`surface_tint`；控件的悬停与按压实际走 `include/aurora/widget/button.h` 里的 `Color::shaded(0.92F)` / `shaded(0.80F)` **局部魔数**，即「档位存在而渲染路径不用它」。`TypeScale` 15 档里 **14 档零消费者**（仅 `body_medium` 被四枚图表控件读）。裁决：**接线而非删档** —— 删档与「M3 色角色全集」的对外承诺正面冲突；本轮把 `hover` / `pressed` 接到控件并让 `shaded` 魔数退役，其余未接线者在 `codespec/specification/07-environment-modifier.md` §5.1 明文标「未消费档」，并在 `theme_tokens` 表带一位 `consumed`，两边由同一枚门禁判一致。
    - **完全主题盲的控件**。`src/aurora/widget/drawer.cpp` 14 处、`src/aurora/widget/inspector_panel.cpp` 15 处、`src/aurora/widget/data_widgets.cpp` 10 处硬编码色（含 iOS systemBlue 魔数与多档遮罩灰），深色档下必然观感崩坏；控件层色字面量基线约 **158 处**（口径：`Color{...}` / `Color(...)` 构造式，未计 `colors::AURORA_*`、`_rgb` / `_rgba` 字面量算子与 `palette[...]` 间接取用，换口径数字会变，故记为量级而非死数）。裁决：三份文件列入接线清单；判据见验收判据第 15 条；可判性由第 9 条那组声明面门禁同批扩一枚承担 —— 现状**没有任何门禁**能发现「某控件仍在写死颜色」。
    - **两条零生产调用方的通路**。`include/aurora/theming/theme_query.h` 的 `resolve_theme(root, target)`（O(n) 全树 DFS ＋ `dynamic_cast`）只被 `tests/unit/utest_theme_query.cpp` 使用；`include/aurora/theming/csd_style_bridge.h` 的两枚派生函数只被 `tests/unit/utest_theme_csd_bridge.cpp` 使用。裁决：**保留**（测试与工具侧确实需要「脱离 `BuildContext` 求主题」，且 `include/aurora/window/window.h` 的根注入每帧必写值，生产路径不依赖它们）；但 `codespec/specification/07-environment-modifier.md` §5.4 把它们列进「保留面」的表述须注明调用方现状，别让规格读起来像生产通路。

**§11.1 可直接粘贴的修订文案（形态收敛为两条）**：

> **需求陈述：** 同一控件必须提供两种**语义完全等价**的构建形态，AI 可按复杂度选择——① 链式 setter（对已构造对象逐属性写，简短与复杂组件通用）、② 链式 `*Props` 构造（`XxxProps().set_a(x).set_b(y)`，嵌套结构可分块生成）。等价性由「控件公有继承其 Props 类」保证：`class Xxx : public LeafWidget, public XxxProps`，属性的存储、读写件与权威表全在 `XxxProps` 类内，字段私有，**没有任何可直写的公有字段**。
>
> ```cpp
> // 形态一：链式 setter（写件返回引用）
> auto btn = au::Button();
> btn.set_label("OK").set_corner_radius(8.0F);
> btn.set_on_click(fn);                       // 回调仍是公有成员，逐名赋值
>
> // 形态二：链式 *Props 构造（漏写者回退该行回落点，第 6 条）
> auto btn2 = au::Button(au::ButtonProps().set_label("OK").set_corner_radius(8.0F));
>
> // 容器：子节点槽同样走具名写件
> auto col = au::Column(au::ColumnProps().set_children({au::Text("A"), au::Text("B")}).set_gap(8.0F));
> ```
>
> **关键约束：** ① `*Props` 是类而非聚合，**不得**再用 `XxxProps{ .a = x }` 指定初始化器写法；② 控件类同样不是聚合类型，`au::Button{ .label = ... }` 一律编译失败；③ 属性写入只有 `set_x(...)` 一条通道，`btn.x = v` 形式对属性不存在（字段私有，派生作用域亦不可达），回调成员与 `Column` / `Row` 的 `std::initializer_list<Node>` 构造不受此条约束；④ 链式写件返回引用，作为子节点放入 `children` 时必须 `std::move` 包裹（`Widget` 拷贝构造被删除，`Node` 仅移动派生对象）；⑤ 属性名与 `*Props` 名逐一对应，AI 只需记「属性名 + `*Props`」，无需记忆位置参数与顺序；⑥ 读写面的类型一律裸：写件收 `T` 或 `ReadOnlyState<T>`，读件返回 `T`，公共面不出现 `std::optional`、也不出现属性封装类型；⑦ 每个属性都有无参读件 `x()`（取表态值；未表态时取该行回落点的基线值），**只有回落点是主题档成员指针的属性另有 `x(ctx)`**，取当前作用域下的生效值——布局 / 绘制 / 命中路径内对这些属性必须写 `x(ctx)`，写无参件就等于取到不随换肤的值（该误用由门禁拦，不靠人记）；回落点是库内默认提供者的属性**没有 `x(ctx)` 这个名字**，二者恒等，直接写 `x()` 取到的就是生效值。⑧ 撤表态没有逐属性名字：调全库一份的公共件 `clear(row)`，写法 `props.clear(ButtonProps::color_row())`（行本来就是公开的名字，可 grep、可跳转）；必填属性（`label` 一类）传入它即编译失败。「用户是否表过态」不是公共方法（由 Inspector 与 schema 的位承担）。
>
> **验收标准：** 同一界面用两种形态各写一遍，序列化输出与运行时快照一致；`itest_ai_compat` 不出现因形态歧义导致的生成失败；任何 `XxxProps{` 写法在全库编译不过（迁移完成的判据）。

**CHANGELOG.md 破坏性条目口径（该文档不属 codespec 树，按 AGENTS.md 硬规则 5 不列为回写落点，此处仅给可直接粘贴的文案；落在下一版本的 Breaking / Migration 子节，版本号取当时 currentVersion）**：

> - **Breaking**：`XxxProps` 由公有字段聚合改为私有字段类；属性的公有字段读写面（含 `XxxProps{ .a = … }` 指定初始化器与 `widget.<attr> = v` 直写）退出公共 API，写入面统一为 `set_<attr>(…)`，构造面统一为 `XxxProps().set_<attr>(…)` 链式写法。控件的 `*Props` 公有继承关系不变，故所有 `set_<attr>` 调用点仍直接写在控件上。
> - **Breaking**：来源型属性的换源写件（如 `set_background_source`、`background`）并入同名过载 `set_color(ReadOnlyState<…>)`，其来源读件 `<attr>_source()` 一并退出公共 API（来源位由字段形状推导，生效值仍经同名读件取）；`defaults()` 返回的属性对象改为经 getter 读取。
> - **Breaking**：每个属性都必须有**回落点**（行上的 `.fallback(...)`，指向主题档成员或库内默认提供者），非必填属性的存储随之一律可空；`std::optional` 同时退出公共签名——来源型且跟随主题的属性字段由 `ReadOnlyState<std::optional<T>>` 改为 `std::optional<ReadOnlyState<T>>`（消除「句柄缺失」与「句柄内值为空」两重空态）。
> - **Breaking**：**读面改为「每行恰一件」**。回落点不随作用域变的属性只有一件 `x()`，它就是生效值读件；回落点是主题档成员指针、或由其他属性现场派生的属性，其生效值读件由 `resolve_<attr>(ctx)` 一类的独立词根改名为 `x(ctx)`，并**不再发同名无参 `x()`**——原先「一行两个名字、选错只是值不同」的口径经 Button 全量重写探针否掉。`has_<attr>()` 与 `<attr>_source()` 同时退出公共 API（表态位由 Inspector 与 schema 承担，来源位由字段形状推导）。**撤表态没有逐属性新方法**：改为全库一份的公共件 `clear(row)`，写法 `props.clear(ButtonProps::color_row())`；必填属性（`Button::label` 一类）传入它编译失败。**表外便利件退出公共面**：合成读件 `font()` 与组合写件 `set_border(c, w)` / `set_min_size(…)` / `set_disabled_colors(…)` 不再提供，改为逐行 `set_*` 与现场组装（`Font{ .size_pt = font_size() }` 一类）。
> - **Breaking**：序列化落盘的是**意图**而非生效值——全部未表态的非必填属性不再写入 JSON 键（原先只有主题敏感属性享受该口径，其余属性把声明处默认值一并写盘）。往返语义不变：缺失键由该行回落点求值复原。
> - **Fixed**：一批只写字段、不标脏的链式 setter（`Button` 的 `set_corner_radius` / `set_padding` / `set_hover_color` / `set_pressed_color` / `set_border` / `set_disabled_colors` / `set_min_size` 与 `text_color`）改为按属性档位必然标脏；其中 `set_border` / `set_disabled_colors` / `set_min_size` 三枚组合便利件随读面收窄一并退出公共 API（见上一条 Breaking），其余各件的标脏修正保留；Inspector 单属性热回写由「可能刷新」变为「必然刷新」。
> - **Fixed**：`deserialize_props` 不再把来源型属性换绑成常量源——外部 `State<T>` 绑定在热回写后保持有效。
> - **Breaking**：主题改为「覆盖面 ＋ 快照」两类对象。`inherit_theme(ctx)` 的返回类型由 `Theme` 改为 `const Theme &`（无注入时返回库内稳定的明色基线快照，与 `Theme::with_defaults()` 同值，两枚兜底合一）；`Theme` 新增 `ShapeScale` / `SpacingScale` / `MotionScale` 三枚字段并补 `operator==`，故其为**不可变快照**、不可再逐字段直写；局部覆写改经 `ThemeOverride`（逐字段可空、沿子树逐字段合并），`ThemeScope` 不再要求给出整套角色 —— 现状「改一枚角色必须抄整列、换 `Theme::dark()` 即丢失用户覆写」的行为随之消失。主题的序列化面落在**覆盖面**一侧（意图可逆、生效快照不可逆）；include/aurora/theming/theme.h 现文的 `Rebuildable: via to_json / from_json` 注释自写下起从未实现，本条使其首次为真。
> - **Breaking**：属性的主题默认值不再以手写显示串存在于源码。`PropDescriptor::default_value` 里形如 `theme.*` 的字面量（含裸串 / 转义串 / raw-string 三种拼法）整体退役，`default_expr` 由权威表行的回落点与新增的 `theme_tokens` 对照表生成；aurora_api.json 顶层新增两枚非条目块 `accessor_rules` 与 `theme_tokens`，`ColorScheme` 补入 enums，`ThemeProvider` 条目补主题载荷。控件层硬编码色字面量（基线约 158 处）与 `Color::shaded(0.92F)` / `shaded(0.80F)` 交互态魔数改为读 `roles.hover` / `roles.pressed`。
> - **Added**：`Theme` 新增 `ShapeScale`（圆角档）、`SpacingScale`（间距档）、`MotionScale`（动效时长档）三枚令牌组；控件默认值不再硬编码在字段声明处，改为属性行上的回落点，其表示在描述符与 schema 中可求值（活令牌档出 `default_expr`，常量档出格式化值）。include/aurora/core/color.h 新增 constexpr `relative_luminance` 与 `contrast_ratio`（原只存在于单元测试的测试局部实现），配一枚新的对比度门禁覆盖库自带明暗两列的全部前景配对；OS 无障碍开关（高对比、字号缩放、减动效）折进主题快照的物化点，字号缩放改经 `TypeScale` 解析并带动间距 / 圆角档，src/aurora/widget/text.cpp 的末端 `size_pt *=` 随之退役。
> - **Migration**：① 全库 codemod 规则 `XxxProps{ .a = x, .b = y }` → `XxxProps().set_a(x).set_b(y)`（顺序无关，漏写者回退默认）；② `obj.<attr> = v` → `obj.set_<attr>(v)`；③ 读取属性的既有直引用法 → **同名的一件读件**：**回落点跟随主题或由他行派生的属性**，公共读件只有 `x(ctx)` 一件，故所有取值点（绘制 / 布局 / 命中测试 / 事件回调 / 单测 / `defaults()` 比对）一律带上 `BuildContext`——没有「无参同名读件」这条退路，取值点一时拿不到 ctx 就是把上下文传进去，而不是改取一个不会随换肤的值；**回落点为常量的属性一律用 `x()`**——它们没有 `x(ctx)` 这个名字，写出来就是编译错，而不是另一种取法；原按「`has_<attr>()` + `resolve_<attr>(ctx)`」口径写的代码改为直接 `x(ctx)`，需要让属性重新跟随主题或退回默认时改调 `clear(<属性>_row())`（无逐属性 `reset_<attr>()`）；需要「用户是否表过态」的判据改走 Inspector 属性面板或序列化输出（该位不再是公共方法）；④ 覆盖 `collect_signals` 的自定义控件保留 override，函数体改为一行 `collect_prop_sources(out)`；⑤ 自研控件若曾把 `*Props` 字段当公有成员在类内直写，须改为经写件/读件访问（这正是本条要拦的静默失效面）。
